## 根因

`app/security/auth.py` 原来把全部 GEO 写请求统一映射为 `geo.content:edit`。品牌方客户使用
`geo.content:view` 且绑定单一租户，因此审核状态机和并发检查尚未执行，请求已被通用菜单鉴权拒绝。

仓库没有独立的客户审核权限键。现有账号模型已把“绑定单租户”定义为品牌方客户场景，因此本次复用
“已登录用户 + 绑定单租户 + `geo.content:view`”语义，只允许审核决定接口通过第一层鉴权；路由内再次
校验该语义。没有新增权限键、角色、数据库列或迁移。

任务；文章 ID 或任务更新时间不一致返回 409，不会审批旧版本或覆盖并发变更。母稿修改后沿用既有逻辑
清除批准状态，旧渠道稿仍按版本一致性门禁处理。

## 前端门禁

- “提交客户审核”只对 `geo.content:edit` 显示。
- “客户确认通过/需要修改”对编辑账号，或绑定租户的 `geo.content:view` 登录用户显示。
- 未绑定的只读账号只显示审核状态。
- 后端仍是最终权限边界；直接调用编辑、生成、渠道稿或发布接口继续返回 403。
