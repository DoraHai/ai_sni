# SEM 拓词页面请求预算（待审核，未发布）

## 依据

PR #248 合并提交 f64e342dd523481e118a6ae1e9626c32e612b714 的一次虚拟客户 20 词
qwen-plus 请求，在 30 秒 HTTP 超时配置下于 30.20 秒触发 ReadTimeout，没有可评分正文。
上一次较长超时的调用耗时 48.23 秒。两次单次观察不是稳定延迟分布；本轮不再调用模型。

## 本轮边界

- `/api/v1/expansion/evaluate` 每次最多处理 5 个去重词、最多一次模型调用。
  默认 limit=5；为兼容旧前端，仍接受 1–20 的 limit，实际取 min(limit, 5)。
  剩余词计入 deferred，游标停在本次实际选择的最后一个词，不自动继续、并发或重试。
- 对带 retry_ids 的请求不能静默截断。超过实际 limit 或 5 个 ID 时，在读客户或调用模型前
  返回明确 422；旧页面可把上限调到 5 后重试，新页面会自动按最多 5 个截取重试队列。
  这样不会让旧页面从队列删除尚未尝试的 ID。多来源同词仍作为一个词处理。
- SEM 模型调用外围增加 asyncio.timeout(30)，覆盖模型等待的总时间；同时传 HTTP timeout=30。
  总时限或传输失败走现有失败路径，保留旧结论、画像标记与人工价格，不写入伪造结果。
  外部 CancelledError 继续传播，不吞掉取消、不触发重试。
- 这是模型等待预算，不是含数据库查询、提交和 JSON 解析在内的整条 HTTP 请求硬截止时间。
  同步解析期间不能被 asyncio 抢占；没有在此实现响应字节/token 硬上限。
- 前端 AI 按钮、确认文案和重试切片统一用 min(所选上限, 5)。候选拉取仍可为 20，
  不改变采样、业务筛选或人工加词。AI HTTP 等待从 10 分钟降为 60 秒，给模型之外操作留缓冲。
  浏览器超时不保证服务器停止，也不证明供应商未计费；不要据此自动重试。

## 未改动的行为

共享 app/ai/deepseek.py、SEO/GEO、真实百度写回、Nginx、数据库 Schema 和迁移均不修改。
提示词、依据判定、价格校验及画像指纹保持不变，不以修改标签或缩减评分分母换取通过。
本次只限制拓词页的交互入口；onboarding_builder 和历史 bulk sync 对评估器的调用仍保留
原来的总词数及批次语义，但每一次 SEM 模型调用同样受 30 秒模型等待预算约束。
没有把历史 bulk 流程悄悄改成“只处理 5 词即完成”，也未新增后台任务。

## 验证与后续

离线测试覆盖：旧 limit=20 实际只请求 5 词、去重及下一批游标、超时不写旧数据、
准确的失败 ID、显式继续、超大重试不丢队列、持续活动仍受总时限、取消传播、无自动重试，
以及前端保留旧失败队列中未选中的词、确认与请求上限一致、采样上限不变。
测试使用 mock，不读取生产凭据，不连接生产数据库或真实模型。

本地结果：11 个相关 Python 测试文件合计 284 passed（1 个既存 jieba/pkg_resources 弃用警告）；
SEM UI 交互契约测试、npm run build、npm run verify:sem-build 均通过，构建门禁检查 98 个 JS 资源。
构建仍有依赖 PURE 注释及大 chunk 提示，未在本次顺带处理。git diff --check 通过。

5 词是保守的工程起点，不是实测证明可用的批量大小。小批次可能增加同一总词量的重复画像
输入成本与人工点击次数；还需另行授权小规模、不同组别的真实模型验证，不能据单元测试发布。

后端与前端需分别审核、分别同步到对应生产分支。优先前端再后端可让界面提前使用 5 词；
若后端先上，旧前端普通请求仍被截为 5，超过 5 ID 的重试会明确拒绝，应调整页面上限或更新前端。
