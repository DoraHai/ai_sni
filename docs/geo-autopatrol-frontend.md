# 每日检测前端验收

入口沿用 `/geo/visibility/snapshots` 的采集页和 `/geo/models` 的平台引擎页。全部客户表放在引擎页顶部，保持平台管理入口集中，同时不依赖当前所选客户逐个加载。顾问卡仅在顾问身份下展示，平台表要求未绑定客户的账户管理编辑权限；最终权限由接口验证。

按 dev/CONTRACT.md v1 实现：开关只提交 tenant_id/enabled/expected_revision，手动次数使用独立 manual_limit_revision。超管仅提供 force_disable/unlock 和次数管理。切换客户会清空新卡状态、取消读取，迟到写响应也不能覆盖新客户。404 显示“功能未就绪”，不会以旧设置接口代写。409/423 刷新后需要再次明确操作，不自动重试写请求。旧频率只在接口确认 legacy 时允许管理员编辑，每日自助客户保持禁用。

不加环境开关，本 PR 无迁移，不修改后端/SEM 权限、部署流程或调度逻辑。依赖 PR1 的兼容 schema 和 PR2 的后端契约实现，发布顺序为后端在前、界面在后；未接后端时可验证未就绪状态。

验证命令：

```powershell
cd frontend
node --test tests/geo*.test.mjs
cd geo-frontend
npm run build
```
