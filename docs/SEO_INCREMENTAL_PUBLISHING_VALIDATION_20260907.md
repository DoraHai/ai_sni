# SEO 分渠道发布验证计划（2026-09-07）

## 目的和当前结论

本轮不等待所有平台账号齐全。每个渠道独立判断是否具备测试条件，具备条件的先完成发布、回执、公开网址、平台状态和正文核验；缺少账号登录、验证码或最终人工确认时，只将该渠道标记为待真人，继续其他渠道及离线验证。

本计划不授权扩大客户、站点、账号或稿件范围，不采购账号，不修改客户网站。工作台联调使用的 `tenant_id=16 / site_id=3 / user_id=5` 只有空列表只读证据，不能据此推定存在可发布稿件或渠道账号；诺德 `site_id=1` 也不作为本轮已获准发布资源。

生产代码基线为 `codex/production-seo` 的 `cc9a2af`。已确认的运行时发布证据为后端 `5ef5bab`、前端 `5a33011`。问答分发空列表入口和 CSDN 渠道配置文案修复均包含在前端版本中；源码与自动化回归已核，部署后浏览器复核本次因现有浏览器没有可复用登录态、跳转登录页而受阻，没有产生写入。

## 单渠道执行顺序

1. **只读核对范围**：记录获准的 `tenant_id`、`site_id`、操作人和渠道配置 ID。确认渠道配置、保险柜凭据、浏览器登录态是三种不同事实。
2. **锁定稿件**：记录内容或回答 ID、审核状态、内容版本、审核人与提交人。只接受当前仍有效、已独立审核且明确可对外发布的版本。
3. **发布前检查**：核对目标平台、目标账号标签、问题或编辑器网址、标题、正文、图片、分类、声明和平台限制。预检通过只表示可以继续，不代表平台会接受。
4. **执行到人工边界**：助手只填写允许的字段；遇登录、验证码、账号确认和最终发布按钮交给真人。未知编辑器结构、已有不同正文或范围不一致时停止当前渠道。
5. **防止重复**：执行前登记任务和版本。提交结果不确定时不直接重发；优先用公开网址或官方作品 ID 恢复关联并查询状态。旧任务、旧回执和已变更稿件拒绝覆盖新记录。
6. **保存回执**：记录分发/发布记录 ID、尝试 ID、账号标签、稿件版本、提交时间、平台返回 ID、审核状态和真实公开 URL。不得记录密码、Cookie、验证码或访问令牌。
7. **分开核验**：人工回填只记 `reported` 或对应的待核验状态；公开 URL 可读且正文匹配后再记正文观测。平台审核通过、正文核验、发现外链和搜索效果分别保存，不互相代替。
8. **按渠道收口**：通过、失败、受阻、平台审核中分别记录。一个渠道受阻不阻止其他渠道继续；只对受影响流程复测。

## 必须保留的验收证据

每次尝试至少保留：日期、前后端版本、获准客户和站点、渠道与本机账号标签、内容/回答 ID 和版本、审核记录、发布记录 ID、尝试 ID、人工确认结果、平台作品 ID 或真实 URL、平台审核状态、回执导入结果、正文核验状态与时间、防重/恢复结果、错误分类和复测结果。

状态必须按事实记录：

- `填稿完成`：只表示文字或材料已进入编辑器。
- `人工已提交`：只表示真人执行了最终提交。
- `平台审核中/驳回`：按平台返回记录，不算公开成功。
- `网址已回填`：只表示操作者报告了 URL。
- `正文已核验`：系统读取公开页面并确认对应当前审核版本。
- `外链已发现`：公开页面存在指向当前网站的真实链接。
- `效果已观测`：来自注明平台和日期的真实指标；不得将站点总点击归给单篇稿件。

## 真人最小需求

每次只需为一个渠道准备以下条件，无需一次提供全部账号：

1. 一个已获准用于测试的客户和站点，以及一个现有目标平台账号；账号密码、Cookie、令牌和验证码不发送给开发人员。
2. 一篇当前已独立审核、确实允许公开发布的稿件。问答还需一个内容匹配的准确问题网址；文章含图时需确认图片使用权、封面和栏目。
3. 真人在本机完成登录、验证码、目标账号核对、平台必填项和最终发布确认。平台自动保存草稿时也由真人确认是否保留。
4. 发布后保留平台给出的作品 ID 或真实公开 URL；如果仍在审核，只报告审核中，不重复提交。

开发侧负责发布前版本核验、材料准备、防重、回执导入、状态同步、正文与外链核验，以及修复真实编辑器暴露的可复现问题。客户网站图片的实际修改由客户完成；开发继续维护待核实、重抓和失败恢复能力，不等待客户反馈才开展其他渠道工作。
