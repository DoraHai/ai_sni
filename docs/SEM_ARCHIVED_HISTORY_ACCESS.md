## 用户 2026-10-19 15:19 / 15:21 的决定

只在以下情况下 blocked：

- 客户有 archived 账户，且没有任何 active 账户；disabled 不算 active。
- 客户有 identity_conflict 行，即使同时有 active 账户仍封锁。
- 客户的 active UCID 同时在其他客户 active，继续失败关闭。

有 active 账户且没有归属冲突的客户保持 ok，包括 active 50661708 + archived 80243027
的 SZ-老虎新材料，以及当前 active 的苏尔寿。全新无账户客户仍是 unbound。

这是用户明确选择的取舍：有在用账户的客户，其归档账户时期无来源派生数据仍可读。
**用户决定不清理旧可疑数据，依靠封锁诺德的 SEM 展示；不做数据隔离清理。**
归档和重新绑定不会自动清除、纠正、验证旧内容的真实业务归属。

## 封锁范围与提示

仅 SEM 入口执行 SEM 身份限制：`_SEM_IDENTITY_GUARDED_PREFIXES` 中的路径，另有
sem_metrics（业务指标置空、identity_blocked）和 sem_tasks（409）。SEM 模块检查
先于身份检查；未开通仍返回原 403「当前客户尚未开通 SEM 模块」，停用/过期仍返回
原「当前客户的 SEM 模块未启用或已过期」，不伪装成归档或冲突。
SEM 任务自身的功能开放开关及顾问既有路由白名单也保留原有响应和权限限制。

SEO/GEO 路径、客户工作台其他模块、客户管理和 OAuth 重绑不因该身份规则而封锁。
全局 tenants 列表只评估当前可用 SEM 模块的客户；未开通、停用、过期的客户不标 blocked。
SEM 专属列表已有模块过滤。切换器身份评估包含 archived 行，但账户展示继续隐藏归档行。

两类提示沿用 `SEM_ACCOUNT_IDENTITY_CONFLICT` code，保证旧前端兼容，业务 message 区分：

- 仅归档：「该客户的推广账户已归档，暂无可用账户，历史 SEM 数据已暂停展示；请超级管理员重新绑定账户或处理历史数据」
- 冲突：「推广账户归属冲突，已暂停展示该客户的 SEM 数据，请联系超级管理员处理」

现有前端和 #770 的 App.vue 按 sem_identity.status == blocked（不按新 code）隐藏业务视图。
诺德会显示封锁页固定标题「推广账户归属冲突，已暂停展示该客户的 SEM 数据」，
描述显示上述「仅归档」实际 message；顶部仍为「推广账户：归属冲突」及
「已暂停当前客户的 SEM 数据访问」。这些旧固定标题未在后端 PR 改写。
