# GEO 编辑保存一致性验收

## 完成内容
- 正文保存以提交时的输入为快照。等待响应期间继续输入时，保留本地新输入，更新服务端版本信息，返回未完全保存状态，阻止调用方继续评分或优化未保存草稿。
- 创作要求保存同样保留请求期间的新输入，并保持本地草稿标记。
- 正文提交携带 expected_article_id。服务端先锁定当前任务，再读取最新版本；非相同内容的旧版本提交返回 409。
- 相同标题、正文、提纲的重试不创建新版本、不使审核失效。比较正文时剔除系统生成的逐句证据附录。
- 增加后端保存回归用例，并加入两个 GEO CI 流程。

## 验证
572 项后端测试、62 项前端测试通过，GEO 独立前端生产构建成功，git diff --check 通过。
测试覆盖新输入保护、延迟响应、客户与任务切换、旧版本冲突、重复保存保持审核状态、首次保存及任务锁先于版本读取。
后端锁顺序采用模拟会话测试；本轮没有运行真实 PostgreSQL 并发压力测试或生产写入。未调用真实模型或发布客户内容。

## 范围与边界
无数据库迁移，未修改 SEM 功能。锁覆盖此手工保存接口；没有宣称其他生成正文接口已统一串行化。旧调用者省略版本字段仍兼容。多页面同时修改创作要求的服务端版本冲突控制不在本轮范围内。
本轮按用户要求完成至本地提交。
