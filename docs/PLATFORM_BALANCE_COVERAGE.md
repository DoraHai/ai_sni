# 超管余额覆盖（2026-10-10）

`GET /api/v1/admin/console/balances` 的全量查询新增 `coverage`。原实时余额、权限、分页和缓存协议不变；按 provider 过滤时 coverage 为 null。

清单来自已有连接目录，补列 SEO 已存在的百度关键词排名、搜狗与 360 商品。覆盖 SEM / SEO / GEO 的 41 个接口或套餐项，不等于 41 个已接入服务，也不等于 41 个独立账务账户。不会汇总不同凭据、套餐、云服务的余额。

接入状态与查询结果分开：SEM 连接取本进程有效设置；独立服务取只读连接登记的布尔状态与时间。没有登记或没有证据时 configured 为 null，不能把 SEM 环境里有没有相同变量当成 SEO/GEO 配置。停用配置显示停用。查询失败保持未知，不以零替代。

| 查询口径 | 服务 | 当前处理 |
| --- | --- | --- |
| 官方余额 | DeepSeek | 原 SEM 有效查询保持；其他模块只有明确托管的连接凭据才可查询 |
| 官方余额 | Kimi | 固定 GET `api.moonshot.cn/v1/users/me/balance`，只取成功的可用/现金/代金券金额 |
| 官方余额 | DataForSEO | 固定免费 GET `api.dataforseo.com/v3/appendix/user_data`，只取成功任务的 USD 剩余金额 |
| 云账务 | 百炼 / 千问、豆包、混元 / WSA、千帆 | 模型或搜索 Key 不代表账务授权；页面列出授权缺口，不假设属于同一云账户 |
| 套餐 | 站长各商品 | 剩余次数与到期日查询接口尚待确认；不调用付费商品接口来试余额，不用历史调用推算剩余 |
| 配额 | PageSpeed | 项目调用配额尚未接通，不显示现金余额 |
| 待接入 | OpenAI / Perplexity 等 | 保留目录，不推断供应商没有官方账务能力 |

Kimi / DataForSEO / 其他模块 DeepSeek 的凭据只取已启用 API 管理中的连接加密覆盖，且有已登记的官方地址。关闭或未审核管理表时不读加密覆盖、不启用管理、不进行迁移。本改动不会复制独立服务环境密钥；只有独立服务环境配置时，仍显示查询凭据待接入。旧指纹层已在线轮换的供应商暂不使用连接原 Key 查询，待其有效运行凭据能被确认后接入。

同一完整查询凭据与接入点复用一条查询结果，覆盖项通过 balance_row_id 指向该结果。不同 Key 不证明不同账务账户，因此仍不累加金额。缓存仅存内部单向指纹和脱敏结果，权限失败先于数据库及供应商查询。

官方依据：[Kimi 余额](https://platform.moonshot.cn/docs/api/balance)、[DataForSEO 免费用户信息查询](https://docs.dataforseo.com/v3/appendix/user_data/)。站长商品的额度不足错误仅证明该次请求失败，不是剩余次数查询接口。

验证涵盖原生回环 PostgreSQL 只读事务、管理关闭时不解密、明确覆盖可解密而响应不含秘密、停用与旧指纹轮换不使用旧 Key、缺登记时未知、官方地址检查、免费查询路径与真实零余额、错误码不返回金额、同凭据去重、原余额权限与账户分页。供应商响应使用替身，没有在测试中调用付费模型或数据商品。
