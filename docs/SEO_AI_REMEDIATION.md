# 单页 AI 辅助整改

开发基线：main `1f2309037e43`。本批不执行迁移，不修改客户官网、当前 TDK、索引指令或发布状态。

## 工作流

站内优化 → 诊断依据列表 → AI 整改草稿。打开弹窗仅查询已有内容任务；必须显式点击“读取公开正文并生成”才读取公开页面和调用已配置的 AI。

- 程序通过现有 IP 固定的 SSRF 安全抓取通道读取 robots 和当前页面，最多 30 秒；无法确认许可、正文不可读、少于 80 字或最终跳转离开网站时停止，不调用 AI。
- 删除脚本、导航、页眉页脚等，最多使用正文前 12000 字。展示截断提示、真实读取时间、原始证据和正文摘要哈希；不是全站或全页覆盖承诺。
- AI 输出仅限 Title / Description / H1 / 正文结构建议及理由、证据 ID。额外字段、空引用、未知引用、HTML、超长结果或丢失原标题/主标题中的大写品牌/型号标识将被拒绝。
- 检测记录与新读取的正文分别标注。证据 ID 有效不等于 AI 推理一定正确；仍需编辑逐项核实。
- 建议可编辑，默认未保存。保存创建 `drafting` 内容任务并保留 `source_page_id`；不要求硬选无关关键词，后续由编辑在内容任务补齐目标关键词再走原审核流程。
- 已有计划/草稿任务：显式追加交接单，保留原文和人工润色正文，携带 `version_count`，并发修改返回 409。不会重复创建来源任务。
- 已进入审核/待发布/已发布阶段的任务：不改写，只提供复制交接单和查看任务。保存成功后不再允许重复点击创建。
- 关闭后未保存的预览会丢弃；已保存结果在既有内容任务持久化。不存在自动审核、自动发布或修改客户网站的路径。

## 额度与隔离

`POST /api/v1/seo/site-pages/ai-remediation` 要求真实登录用户、当前 SEO 订阅、`seo.site` 和 `seo.content` 编辑权限，并校验 tenant/site/page 三重范围。

额度保存在现有 `TenantModule.module_settings.seo_page_ai_usage`，没有新表/迁移。客户级数据库行锁并强制刷新 ORM 状态，避免多进程或已加载身份对象导致竞态。每日 CST 20 次成功/在途预约、100 次失败重试保护上限；同客户同时间一条。失败按预约日期和 token 返还整改额度，不错误返还新日/新请求额度。进程异常退出的预约保守占额度，120 秒后允许重试；不承诺 exactly-once 外部 AI 计费。

单次请求总时限 80 秒、AI 45 秒、不自动重试。使用已有百炼/DeepSeek 配置，不新增供应商、不输出密钥或供应商异常原文。100 次保护上限是防滥用次数，不是客户成功额度。

## 前端范围切换修复

线上验收发现：切到没有网站的客户，旧站内问题中心仍显示前一客户统计。SEO 路由视图现在按客户重建，站内视图额外按网站重建，立即丢弃旧页面状态/弹窗；旧页面异步网站列表不得重新写入全局选择。

此改动不替代后端租户鉴权。上线时还须在生产兼容分支保留原问题中心、异步抓取和导出功能，不得用 main 整个站内文件覆盖生产版本。
