# SEM 多渠道入口预留

## 本次边界

仅前端；`migration=not-run`。不接入任何新平台，不修改百度业务、后端、数据库、
鉴权、Nginx 或其他模块，不将入口可见解释为账户已授权。

侧栏新增“广告渠道”：仅列三个待开放渠道；百度继续使用“投放管理 → 推广账号”
的现有 `/sem/accounts`，避免重复菜单路径导致同时高亮。三个独立静态页面为
`/sem/channels/bing`、`/sem/channels/360`、`/sem/channels/soso`。
三个页面统一显示“待开放”，没有授权、同步、执行按钮、模拟报表或开放日期承诺。
复用 `sem.assets` 菜单权限和现有登录守卫，不新增角色权限。
页面隐藏百度账户状态与真实回写横幅，避免误认为新平台已开启回写。
外壳仍保留已有客户切换与百度导航徽章的只读加载；占位组件本身无网络调用。
不改变任何已有业务路由或租户访问守卫。静态页面不包含客户业务数据。

## 平台名称及未来接法（设计，不是已实现能力）

- 必应：后续评估 Microsoft Advertising，先核验国内账户资质、授权及 API 权限。
  参考 https://ads.microsoft.com/ 。不因添加入口扩大为海外营销产品。
- 360：后续评估点睛开放平台，先确认开发者资质及当前 API 协议。
  参考 https://open.e.360.cn/intro/ 。
- 搜搜：暂保留需求原名，真实平台待负责人确认；不能自动等同搜狗或腾讯广告。
  `soso` 仅 UI 占位 ID，不预先固化数据库 provider 标识。

正式接入分阶段独立审核：资质/授权 → 只读账户与报表 → 管理能力 → 受控真实写回。
每阶段都有能力开关，未支持的操作不展示成可执行操作。
未来账户标识至少隔离 tenant + platform + external_account_id；不复用百度 UCID。
金额币种、报表时区、转化口径分别定义，不直接跨平台相加或用百度数据填空。
写回台账、幂等键、审批 fingerprint、资金锁都要覆盖平台和账户；不能继承百度授权。
公共体验可复用，平台 API 适配器及安全校验必须独立；Schema 另行诊断审核。
