# GEO 详细使用说明（运营操作手册）

面向一线运营、实施、交付。按「一个新客户从开户到对外汇报」把每一步写清：点哪里、系统会做什么、什么能对外说、什么绝对不能当结论。

菜单级速查见 [`USER_GUIDE.md`](USER_GUIDE.md)。指标公式见 [`GEO_METRIC_DICTIONARY.md`](GEO_METRIC_DICTIONARY.md)。本地端口见 [`LOCAL_GEO_DEMO.md`](LOCAL_GEO_DEMO.md)。

**两条产品线不要混测**：GEO 是 AI 搜/问里的品牌可见度与内容闭环；SEM 是百度搜索广告。同一个客户里可以两套都开，但开户、词库、报告都要分开看。

---

## 1. 先搞清系统在帮你做什么

GEO 闭环只有四件事：

1. **问**：用真实用户会问的品类题，去问多家生成式引擎。
2. **记**：记下「有没有提到本品、排第几、引用了哪些 URL、顺带提到哪些竞品」。
3. **补**：缺可见度就写可核验的内容，发到官网/知乎/微信等，再把发布 URL 登记回来。
4. **比**：下一轮巡检看提及、引用有没有变化。样本不够就说「还不能判断」，不要写成「提升了 100%」。

系统**不会**保证被 ChatGPT / 豆包引用，也**不会**用 GEO Score 当发布开关。Score 只是母稿结构就绪度。能不能发，看事实是否够、有没有编造、渠道稿有没有过成文门控、人有没有审过。

## 2. 本地从哪一页开始（不用测登录）

推荐入口：

```text
http://127.0.0.1:5173/geo/overview
```

前提：前端 `:5173`、主站 API `:8000`（或 GEO API `:8011`）已启动，本地带 `VITE_API_KEY=geo-demo-local-key`。

顶栏切**客户**。所有事实、意图词、任务、快照都按客户隔离。演示客户常见是：

| 客户 | 用途 |
| --- | --- |
| 默认演示租户 | 老数据，别拿来当新品牌验收 |
| 智齿 | 已有客服赛道样本时用 |
| **Udesk优地** | 新客户点击测试起点 |

没有登录账号时，页面应能直接进 GEO；不要卡在验证码登录页。若仍被踢到 `/login`，用顶栏「跳过登录 / 进入工作台」，或确认前端已配置 API Key。

## 3. 新客户开户（约 15 分钟）

路径：`/geo/overview`（开户向导 `/geo/onboarding` 已下线；品牌资料改在 `/geo/brand`）

### 3.1 填官网，先预览

1. 填公网可打开的 `https://` 官网（要 HTTP 200）。内网、需登录、虚构域名都会失败。
2. 建议打开「百度下拉扩展」，词更接近真实问法，会稍慢。
3. 点预览。不要一上来就「确认写入」。

核对这四块：

| 块 | 该留什么 | 该丢掉什么 |
| --- | --- | --- |
| 业务线 | 产品线名称（如 Udesk 智能客服） | 标题切开的碎片：「AI」「官网」「平台」 |
| 意图词 | **品类可见度**题：不带品牌（「在线客服系统怎么选」） | 牙膏/招聘/拼音/下载；带品牌的题只留少量并标探测 |
| 事实卡 | 能核验的产品能力、口径、案例原文 | 导航垃圾句、重复标题、空「待补」 |
| 引擎 | 先启用 2 个以上 | 未配 Key 就开定时巡检 |

「品类题」和「探测题」必须分开：

- 品类题：用户没点名品牌时，AI 会不会提到你 → 计入**品牌提及率**。
- 探测题：已经点名「Udesk 怎么样」→ 只计入**点名认知率**，几乎总会提到品牌，**不能当可见度**。

### 3.2 写入

可先「演练（不写库）」看将创建多少业务 / 意图词 / 事实，再「确认写入」。写入前系统会再确认目标客户，避免写到隔壁租户。

写入后系统会：

- 建业务线 + 默认单元。
- 意图词挂到匹配业务下的默认单元。
- **事实自动挂到开户业务**，不再默认「租户共用」。旧数据里未挂业务的开户事实，打开本页就绪检查时会补挂。
- 同域名官网渠道会复用；名称「官网」已被占用时建成 `官网 · 域名`。
- 可选做 sitemap 审计（缺页提示），不要把审计失败当成开户失败。

就绪清单要先齐这几项，再谈巡检：品牌词、业务、意图词、**已核验事实 ≥ 3**、引擎、AI Key。定时巡检可以后开。

## 4. 事实库：生成内容的唯一证据

路径：`/geo/facts`

### 4.1 什么能当事实

一条事实必须是**原子、可核验**的陈述，例如：

- 「Udesk 支持网页、微信、邮件等多渠道接入。来源：官网产品页。」
- 「标准实施周期约 14 天。来源：实施手册 2026。」

不要写：

- 「行业领先、头部客户众多、识别率极高」（没法核）。
- 把整页官网粘成一条超长陈述（超过约 220 字核验会被拒，请拆条）。

类型建议：产品 / 指标 / 案例 / 政策。有数字的标「指标」，有客户名的标「案例」，并且数字、客户名必须在陈述里写出来，后面正文才能用。

### 4.2 业务归属

列表「业务」列：

- 有业务名：只给这条产品线用。
- **租户共用**：所有业务都能绑。开户抽上来的事实**不应**长期停在共用。若仍显示共用，打开开户向导触发补挂，或编辑里手动选业务。

任务编辑器绑事实时，会优先当前任务所属业务，共用事实仍可选。

### 4.3 核验（必须填依据）

信任级：`草稿` → `待审` → `已核验`。

生成母稿至少绑定 **3 条已核验**事实。来源名称必填。

**不能**在编辑里把信任级直接改成「已核验」，也**不能**点一下「核验」就过关。点核验后必须填：

| 字段 | 怎么填 |
| --- | --- |
| 摘录原文 | 必须是本条陈述里的**连续原文**，不是自己改写 |
| 摘录定位 | 源页位置，如「官网首页 · 产品能力 · 第二段」 |
| 来源 URL | 能打开的页面；事实还没有 URL 时这里必填 |
| 备注 | 可选，如「2026-08 与销售口径核对」 |

保存后，列表会留下定位和核验时间。系统同时记录核验人。没有摘录/定位的旧「已核验」仍可用来生成，但补核一遍更稳。

开户抽到的多条事实标题可能都叫公司名，**以正文区分**再核验。

## 5. 意图词与监测准备

### 5.1 意图词 `/geo/prompts`

- 品类题用完整问句，不要只丢品牌短词。
- 编辑里打开「品牌探测」= 探测题。
- 未挂单元的词会进日指标未分类桶，业务详情里看不到。
- 「智能推荐」请填品类词（智能客服、在线客服），不要只填「Udesk」。

建议每个客户至少：3 条以上品类题 × 2 个以上引擎，否则交付会显示「样本不足」。

### 5.2 AI 配置 `/geo/ai-settings`

租户级大模型 Key。本地常用阿里云百炼 OpenAI 兼容。未配时可用环境变量兜底。  
母稿、渠道成稿、巡检真采样都走这里。

### 5.3 引擎 `/geo/engines`

| 采样模式 | 含义 |
| --- | --- |
| `openai_compat` | 真采样，要 Key / base_url / model |
| `mock_persona` | 人设模拟该引擎语气，**不能当客户效果** |

监测定位：

| 定位 | 行为 |
| --- | --- |
| hybrid（默认） | 有 Key 真采，没有则模拟 |
| simulation | 全部模拟 |
| real_only | 没有真 Key 的引擎直接跳过 |

**不要**在没配 Key 时打开定时巡检，会持续灌模拟数据，交付页会一直「含模拟 / 不能对外」。

### 5.4 巡检 `/geo/visibility/patrol`

1. 意图词上限先用 5～10 条，确认落库后再加大。
2. 引擎空选 = 所有已启用。
3. 「自动落库」关闭则只看明细，不进报表。
4. 跑完去「AI 可见度」核对：品类题提到了谁、有没有引用 URL、竞品名是否乱标。

日配额默认每客户 24 次。探测提示会带品牌参考名；品类题若仍 100% 提到本品，先怀疑提示词把品牌喂给了模型。

## 6. 写一篇能过门禁的内容

路径：缺口工作台 `/geo/gaps` 建任务，或优化文章 `/geo/tasks` 新建，进入编辑器 `/geo/tasks/:id`。

### 6.1 内容策略（Brief）

行业、受众、意图、内容类型、CTA 必填后保存。  
「AI 建议」按**当前客户品牌**生成，不是按任务业务线。客户是泵业、任务写客服时建议会串台，手改后再保存。

禁用表述、必须覆盖的实体、竞品名可以填，系统会尽量守住；**不能**靠 Brief 让模型编出事实卡里没有的数字。

### 6.2 绑事实

至少 3 条**已核验**。左侧「当前绑定」能看到正文和来源。  
3 条全是「官网一句话介绍」、里面没有任何数字和案例时，后面正文也**不许**出现识别率、满意度、成功案例、头部客户。要写这些，先补对应事实并核验。

### 6.3 生成母稿

点「生成母稿」。这是**内部草案**，不能当正式发布文。

- 任务进后台排队，页上会显示进度（准备事实 → 调模型 → 挂引用）。
- 可以取消；取消后正文不会被半成品覆盖。
- 刷新页面不会丢任务，横幅会把未完成作业接回来。
- 失败会给出原因，可重试。

生成后看两处：

1. **逐句证据**：哪些句子挂上了事实卡，哪些标「未挂事实」。未挂的句子不能当成已核验。
2. **检查就绪**：编造扫描不过（无依据数字 / 性能 / 案例 / 占位名）时：
   - 就绪为否；
   - Score **最高 59**，不再出现「98 分还标可发布」；
   - 渠道稿即使上次标过「HTML 可发布」，有编造时也会收回。

Score 是结构分，不是发布许可。结构齐、事实空，照样不能发。

### 6.4 改稿原则

正文只能复述已绑事实。没有的数据写成「以官方公开资料为准」，不要补行业常见值。  
「检查就绪」里的数字项：事实卡没有数字时，不再倒逼你编三个百分比。

### 6.5 渠道成稿

勾选官网 / 微信 / 知乎等 →「AI 生成正式渠道稿」。

- 未在「发布渠道」启用的类型不会出页签。
- 勾了 3 个只出 2 个：失败渠道未过完整文章门控（提纲感、过短、缺表、**编造**），页上有原因，可重试失败渠道。
- 微信要完整段落，不要小标题下只堆要点。
- 只有 `publish_ready` 且编造扫描为 0 才能显示「HTML 可发布」。带警告、规则裁剪稿都不是成稿。

默认看「正稿预览」。复制出去的是 HTML，不是 `##` 标记。

### 6.6 审校与发布

1. 提交审校。默认不能自己审自己。
2. 通过后再推送或导出。
3. **必须回填已发 URL**（或走已配置 Webhook / 社交账号）。不回填，后面无法把引用对回这篇文章。
4. 「发布后效果」看发布前后窗的提及率。任一侧样本不够时显示「—」和原因，不要把空白当 0%。

## 7. 竞品监测（真实引用 / 推定 / 外部检索必须分栏）

路径：`/geo/competitors`

竞品名来自快照上的 `competitors` 标注，不是事先维护的竞品库。没巡检、没填竞品时列表为空是正常的。

### 7.1 主列表怎么读

| 列 | 含义 |
| --- | --- |
| 出现 | 多少条快照点过这个名字 |
| 来源 | 这些快照里**真实 cited_urls** 去重数 |
| 平台 | 这些 URL 对上的渠道种数 |
| 提问 | 覆盖多少条不同意图词 |

页顶有与交付摘要同一套**样本门槛**（真采样条数、提问数、引擎数）。不达标时：

- 同题对比、日监测里的比率显示「**样本不足**」，**不会再出现单题 100%**；
- 标签是「不适合对外汇报」。

别名：把「七鱼」「网易七鱼」收成一行。只影响展示，不改库里的原始名。

### 7.2 点开一家竞品（溯源抽屉）

三步：选来源 → 写洞察/行动 → 生成并确认报告。

**三栏不要混：**

| 栏 | 是什么 | 能不能当「检索到的发布位置」 |
| --- | --- | --- |
| 真实引用 URL | 本次 AI 回答里的 `cited_urls` | 能，计入来源数 |
| 推定参考阵地 | 内置阵地库（Udesk / 七鱼 / 美洽等官网） | **不能**。只是「这类产品通常出现在哪」 |
| 外部检索候选 | DuckDuckGo 公开检索，或检索失败时的已知官网回退 | **不能**自动计入来源。必须人工勾选确认 |

外部检索每条会打标：

| 标记 | 含义 | 建议 |
| --- | --- | --- |
| 官方域名 | 与阵地库官网一致（如 `udesk.cn`） | 可优先确认 |
| 疑似仿冒/抢注 | 同品牌不同后缀（如 `udesk.com`） | 默认不要当官网 |
| 营销/目录站 | 软件目录、软文站 | 最多当线索 |
| UGC/评测 | 知乎专栏、问答 | 需人工看是不是竞品自己发的 |
| 未核验域名 | 其它站点 | 打开看过再勾 |

勾选确认后，才会写入报告附录「人工确认的外部检索页」，并注明**不是**本次快照 `cited_urls`。不计入来源数。

### 7.3 报告

生成并保存草稿 → 改洞察/行动（会自动保存）→ 确认 → 归档。  
可导出 Markdown / 可打印 HTML，也可从结论一键建内容任务。  
报告按客户隔离，可挂业务线和期次。

## 8. 交付与对外口径

路径：`/geo/overview`（导出报告）。独立交付摘要页 `/geo/deliverables` 已下线，只读分享仍为 `/geo/deliverables/share/:token`。

对外只看包装后的口径，不要从竞品表、单题快照截 100% 给客户。

必须同时交代：

- 观察期（顶栏 7 / 14 / 30 / 90 天，上海日历日）；
- 真采样 / 模拟 / 人工各多少；
- 提问数、引擎数；
- 「可对外汇报」还是「未形成有效结论」。

默认门槛（客户交付）：真采样 ≥ 8、提问 ≥ 3、引擎 ≥ 2，且模拟不能压过真采样。不达标就写「样本不足，不能把单次命中写成 100%」。

含模拟时必须写「含模拟，仅内部预判」。`real_only` 导出在样本不合格时会拒绝。

发布影响统一说「发布后观察到的相关变化」，**不要**宣称确定因果。

## 9. 建议工作节奏（一个客户一周）

| 日 | 做什么 |
| --- | --- |
| D1 | 开户、核验 ≥3 条事实、补品类意图词、配 Key、小规模巡检 |
| D2 | 看缺口，建 1～2 个任务；策略 + 事实 + 母稿过编造门禁 |
| D3 | 出官网/知乎成稿，审校，发布并回填 URL |
| D4～D5 | 再巡检，看任务「发布后效果」、引用有没有打到自有域 |
| D6 | 竞品溯源：真实引用 + 人工确认的外部页，出一份报告草稿 |
| D7 | 交付摘要：样本够才给客户看比率；不够就只给过程和下周计划 |

## 10. 点击验收清单（Udesk优地）

1. 打开 `http://127.0.0.1:5173/geo/overview`，顶栏切到 **Udesk优地**。
2. 事实库：#40～#45 应挂在 Udesk 业务，不是租户共用。点核验必须填摘录和定位。
3. 打开任务（如 #12）：若只绑了 3 条泛化官网事实，正文里却有识别率/案例/具体数字，点「检查就绪」应**不通过**，Score ≤ 59，渠道稿不能标可发布。
4. 补 3 条带数字或案例的已核验事实（或删掉稿里的编造）后再生成，逐句证据应能挂上对应事实卡。
5. 生成过程中刷新页面，进度还在；可点取消。
6. 竞品监测：样本少时比率是「样本不足」。打开 Udesk / 七鱼，点「检索公开页」，应能看到官方 / 仿冒 / UGC 分标；只勾官方后再生成报告，附录有「人工确认的外部检索页」。
7. 交付摘要：同一套「不适合对外汇报」提示，不要和竞品页口径打架。

## 11. 常见误判

| 现象 | 正确读法 |
| --- | --- |
| 探测题 100% 提及 | 点名题，不是可见度 |
| hybrid 下模拟 100% | 演示用，不能写进客户报告 |
| 单题 1 条快照 100% | 样本不足 |
| 母稿 Score 98 | 结构分，不等于可发布 |
| 3 条官网介绍却写出「识别率 98%」 | 编造，检查应失败 |
| 竞品「推定官网」 | 不是本次 AI 引用 |
| 外部检索到 `udesk.com` | 仿冒风险，不要当官网 |
| 开户事实显示租户共用 | 应挂开户业务；打开开户页会补挂 |
| 点一下就已核验 | 旧行为；现在必须填摘录定位 |
| 发布后效果是 0% | 无样本应是「—」 |
| 渠道勾 3 出 2 | 失败渠道未过成文/编造门控 |

## 12. 明确不会自动做的事

- 不会把 SEM 账户、关键词和 GEO 意图词合成一套。
- 不会在没 Key 时自动开定时巡检。
- 不会用 Score 卡发布（卡的是事实、编造、成文、审校）。
- 不会把外部检索结果自动算进引用数。
- 不会保证任何引擎收录或排名。

做完以上，一个客户才具备「能写、能发、能监测、能对外说话」的最低条件。
