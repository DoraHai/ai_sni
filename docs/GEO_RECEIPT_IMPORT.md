# GEO 发布链接回执

在「分发记录 → URL 回填 → 导入回执」上传。一次仅处理当前文章和所选项目；没有项目归属的历史文章需先由有权限的人员设置归属。先预览每行「能导入／不能导入／无需导入」及原因，再确认；有错误时整批不写，重复行跳过。确认会重新校验当前审核、项目归属和发布条件。文章须先通过客户审核。

支持 UTF-8 CSV/JSON，最多 2 MB、200 行。沿用 SEO #670 的容器与上限，但只登记 GEO 已发布链接，不处理 SEO 发布单、账号和三态任务，两者不是直接互导协议。无网络抓取、无自动发布。

CSV 模板（全部是假数据，编号、名称、链接须替换）：

```csv
article_id,platform,channel_name,variant_id,public_url,published_at,note
999999,官网 / 博客,,,https://example.com/demo-article,2026-10-20T09:30:00+08:00,假数据示例请替换
999999,百度贴吧,,888888,https://example.com/demo-tieba,,假数据示例请替换
999999,其他,示例科技社区,888888,https://example.com/demo-community,,假数据示例请替换
```

JSON 使用同字段对象数组，例如：

```json
[{"article_id": "999999", "platform": "other", "channel_name": "示例科技社区", "variant_id": "888888", "public_url": "https://example.com/demo-community"}]
```

- `article_id`：当前 GEO 文章任务编号（不是母稿版本号），支持文本或整数。
- `platform`：填下表中文名或代码；也兼容当前文章已有渠道稿的原渠道代码、画像名称及同值注册渠道名称。未知或有歧义的名称会拒绝，不猜测目标渠道。
- `channel_name`：仅在 `platform=其他/other` 时填写。必填，去除首尾空格后最多30个字，不能空白、纯符号、换行或含不可见字符。自填名不能直接写进 `platform`，避免和标准渠道混淆；其他渠道请留空。
- `variant_id`：没有对应渠道稿时（含“其他”）必填，选择本文章中实际发表的来源渠道稿编号；页面会列出可选编号。已有对应渠道稿时可留空自动匹配，也可明确选择本文章中的实际来源稿件。来源必须属于当前文章且对应最新母稿，不能只拿母稿版本编号，也不能借用其他文章的稿件。
- `public_url`：完整 `https://` 地址，不含账号信息或空格，最多2000字。
- `published_at`：可省略或留空，留空按导入时刻登记；非空须带时区，如 `2026-10-20T09:30:00+08:00`，入库转 UTC。
- `note`：可省略，最多1000字。

范围与单条 URL 回填一致：目标渠道无需另建渠道稿，但必须明确关联本文章实际发表的渠道稿，不自动创建稿件、不绕过母稿和客户审核门禁。发布记录关联来源稿件的 `variant_id`，`channel` 保存目标代码；“其他”则保存自填名，并沿用单条回填的监测 `channel_name` 元数据。渠道列表和名称规则来自共用配置，来源解析及最终写入函数也与单条回填共用。

开发维护只编辑 `app/geo/content/backfill_channels.json`，运行 `python scripts/generate_geo_backfill_config.py` 生成前端副本；回归测试会检查副本与来源一致，避免浏览器和后端口径漂移。

可选 `tenant_id/project_id` 必须与本次选择一致；可选 `status` 仅接受 `published` 或空值。未知字段拒绝。跨客户、跨项目、其他文章或未知稿件编号统一提示不属于当前范围，不透露是否存在。

同一链接（忽略主机大小写、默认端口和页内锚点，保留查询参数）不会重复写入。渠道记录按「来源稿件 + 目标渠道」识别，同一来源可以登记不同目标渠道；同一渠道记录填不同链接要求先核对，已有其他链接不覆盖。整批原子写入，任一行失败全不写；写入期间发生变化也整批回滚。沿用权限、顾问授权、GEO 开通、项目归属及加锁发布门禁，不加迁移。
