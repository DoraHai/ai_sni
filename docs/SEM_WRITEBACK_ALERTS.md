# SEM 真实回写待对账告警

每 5 分钟独立巡检已开通且未过期的 SEM 客户。真实回写台账进入
`reconcile` 时，在下一次巡检生成 P1 告警；`pending` 持续至少 15 分钟
后生成告警（正常运行时最迟约 20 分钟被发现）。演练、成功和明确失败记录不在本轮范围内。

告警出现在现有异常告警列表及未处理告警计数中，包含客户、账户、动作、记录编号和等待时长。
运营应打开“效果验证 → 人工对账队列”，核对百度实际结果后完成对账。
仅点击告警“标记已处理”不能代替对账：源台账仍未决时，下次巡检会重新打开告警。
源记录结束未决状态后，下一次巡检自动关闭对应告警。

同一记录跨天重复巡检也复用原告警；两种台账通过不同实体键区分。
等待时长以台账的数据库生成时间与同数据库会话的当前时间计算。
每客户独立事务；失败会回滚该客户的告警变更并记录日志，其余客户继续。
账户已停用也不隐藏该客户历史的未决记录。

本轮仅实现站内告警。不发送邮件或聊天消息，不自动重试百度写入，不替运营判断资金执行结果。
失败率统计、幂等拦截统计与独立首页待对账卡片属于后续范围。

复用现有 alerts、bid_writebacks、writeback_actions，不更改 Schema，migration=not-run。
发布仅需常规 SEM 后端同步 PR 和受控后端发布流程。
验证包含 PostgreSQL 查询编译、去重键/跨天边界、演练排除和客户事务隔离；
尚未在真实 PostgreSQL 上完成集成验收，上线前应在隔离测试库验证重复巡检与自动关闭。
