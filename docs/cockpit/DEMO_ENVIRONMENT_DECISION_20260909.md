# 全域演示环境架构决定

## 推荐方案

为“G-Snipers 全域演示”建立独立演示运行环境和独立数据库。演示前端沿用正式产品构建，演示后端只连接演示数据库；账号、租户和三模块数据不进入生产业务库。

建议入口：`https://demo.gsnipers.snipers.com.cn/`。若暂时不能增加子域名，可使用独立上游服务承载 `/demo/`，但不能仅靠前端路径把演示请求继续写入生产数据库。

## 选择依据

- SEM 演示账号必须保持不可同步、不可 OAuth、不可写回；现有默认查询只读取 active 账号，而 active 又是大量生产任务的候选条件。
- SEO 演示站点必须保持不可抓取、不可发布；现有工作台只选择 active 站点，而 active 又会进入多个调度器。
- GEO 演示回答必须明确为 simulated，按正式指标契约应被排除；演示需要另行展示虚拟环比，不能改写正式指标口径。
- 在同一生产库增加共享 `data_mode` 仍需逐一修改和证明全部同步、生成、审核、发布、指标重建入口，风险和回归范围明显更大。

## 目标拓扑

1. 独立数据库：建议 `gsnipers_demo`，或数据库负责人批准的等价隔离数据库；不得使用生产业务 schema。
2. 独立服务配置：SEM、SEO、GEO 后端使用演示数据库账号，只允许演示库；所有外部凭据为空。
3. 独立调度策略：演示服务不启动 scheduler/worker；服务端写动作再以 demo mode 硬拒绝，形成双重保护。
4. 独立认证：创建普通演示用户，只能访问演示租户；不使用超级管理员或生产客户账号。
5. 同版前端：界面和正式产品保持同一代码版本；全局固定显示“全虚拟演示数据”。
6. 可恢复夹具：每次演示前可将数据库恢复到固定快照；恢复只能作用于演示库。

## 数据库负责人需要回复

请只做可行性核对，暂不建库、不建表、不写数据：

1. 当前 RDS 是否允许创建与生产业务库分离的 `gsnipers_demo` 数据库；若不允许，请给出可用的独立数据库或独立实例方案。
2. 是否可以创建仅能访问演示数据库的服务账号，禁止访问生产数据库和其他 schema。
3. 三模块现有迁移能否在空演示库完整执行；列出共享 `public.tenants/users/roles/tenant_modules` 依赖和冲突。
4. 演示库是否允许长期保留，并支持执行前快照、固定夹具恢复和整库重建。
5. 推荐的备份、恢复、审计和凭据交付方式；不得在聊天或文档中发送密码。

请返回：可行/不可行、推荐数据库名称或实例、账号权限边界、迁移依赖、预计工作量和明确阻塞项。收到回复前不执行任何数据库变更。

## 服务器负责人需要回复

请只做可行性核对，暂不改 Nginx、不部署、不启动服务：

1. 是否可以提供 `demo.gsnipers.snipers.com.cn`，或等价的独立 `/demo/` 上游服务。
2. 是否可以运行独立的 auth/SEM/SEO/GEO demo 服务，并通过独立环境变量连接演示数据库。
3. 是否能确保 demo 服务不启动 scheduler、worker、自动同步、抓取、模型任务和发布任务。
4. TLS、Nginx 路由、端口、日志、健康检查和回滚目录建议。
5. GitHub Actions 是否建立独立 demo 部署工作流，且不能复用生产部署目标或生产 secrets。

请返回：建议入口、服务/端口方案、配置隔离方式、需要新增的部署模块、预计工作量和明确阻塞项。收到回复前不修改线上路由。

## 后续开发

- 工作台：演示标识、客户故事线、丰富图表、下钻、紧急事项、行动台账和引导式对话。
- 三模块：把各自 JSON/manifest 映射成仅面向空演示库的加载器，并补重复加载、快照恢复和外部动作拒绝测试。
- 审查：逐模块审查后再做跨模块审查；精确 SHA、CI、迁移预览和部署结果全部写入协调文档。
