# 全域演示环境架构决定

## 推荐方案

“G-Snipers 全域演示”继续使用现有产品入口 `https://gsnipers.snipers.com.cn/workspace/cockpit`。用户登录现有系统后，通过工作台客户选择器切换到“G-Snipers 全域演示”，不增加新域名、新登录入口或另一套客户可见系统。

隔离只放在服务端：正式 Auth 保存演示账号、角色和租户身份；工作台识别演示租户后，由服务端演示数据适配层读取独立演示数据库。浏览器不直接决定数据源，三个模块的生产业务表不写入合成数据。模块详情页仍使用现有站内路径，并继承同一个演示租户上下文。

## 选择依据

- SEM 演示账号必须保持不可同步、不可 OAuth、不可写回；现有默认查询只读取 active 账号，而 active 又是大量生产任务的候选条件。
- SEO 演示站点必须保持不可抓取、不可发布；现有工作台只选择 active 站点，而 active 又会进入多个调度器。
- GEO 演示回答必须明确为 simulated，按正式指标契约应被排除；演示需要另行展示虚拟环比，不能改写正式指标口径。
- 在同一生产库增加共享 `data_mode` 仍需逐一修改和证明全部同步、生成、审核、发布、指标重建入口，风险和回归范围明显更大。

## 目标拓扑

1. 单一客户入口：继续使用现有登录、工作台和模块页面；客户选择器中显示“G-Snipers 全域演示”。
2. 独立数据存储：建议 `gsnipers_demo`，或数据库负责人批准的等价隔离数据库；不得把合成模块数据写进生产业务 schema。
3. 服务端路由：现有 API/BFF 根据服务端鉴权后的演示租户标记选择演示数据适配层；前端传入的普通 `tenant_id` 不能单独触发切库。
4. 独立服务配置：演示适配层只使用演示数据库账号，所有外部凭据为空。
5. 独立调度策略：演示运行单元不启动 scheduler/worker；服务端写动作再以 demo mode 硬拒绝，形成双重保护。
6. 演示身份：创建普通演示用户，只能访问演示租户；超级管理员也可在现有工作台切入该租户。
7. 同版前端：界面和正式产品保持同一代码版本；全局固定显示“全虚拟演示数据”。
8. 可恢复夹具：每次演示前可将数据库恢复到固定快照；恢复只能作用于演示库。

## 数据库负责人需要回复

请只做可行性核对，暂不建库、不建表、不写数据：

1. 当前 RDS 是否允许创建与生产业务库分离的 `gsnipers_demo` 数据库；若不允许，请给出可用的独立数据库或独立实例方案。
2. 是否可以创建仅能访问演示数据库的服务账号，禁止访问生产数据库和其他 schema。
3. 三模块现有迁移能否在空演示库完整执行；列出共享 `public.tenants/users/roles/tenant_modules` 依赖和冲突。
4. 演示库是否允许长期保留，并支持执行前快照、固定夹具恢复和整库重建。
5. 推荐的备份、恢复、审计和凭据交付方式；不得在聊天或文档中发送密码。

请返回：可行/不可行、推荐数据库名称或实例、账号权限边界、迁移依赖、预计工作量和明确阻塞项。收到回复前不执行任何数据库变更。

## 服务器负责人需要回复

请只做可行性核对，暂不改 Nginx、不部署、不启动服务：

1. 在保持现有 `gsnipers.snipers.com.cn/workspace/cockpit` 和现有登录入口不变的前提下，建议由现有 API/BFF 内部路由，还是由同域隐藏上游承载演示数据适配层。
2. 是否可以运行仅供内部调用的 SEM/SEO/GEO demo 数据服务，并通过独立环境变量连接演示数据库；不得增加客户可见的新网址。
3. 是否能确保 demo 服务不启动 scheduler、worker、自动同步、抓取、模型任务和发布任务。
4. TLS、Nginx 路由、端口、日志、健康检查和回滚目录建议。
5. GitHub Actions 是否建立独立 demo 部署工作流，且不能复用生产部署目标或生产 secrets。

请返回：同域内部路由方案、服务/端口方案、配置隔离方式、需要新增的部署模块、预计工作量和明确阻塞项。收到回复前不修改线上路由。
