# G-Snipers 平台管理中心设计

日期：2026-09-07  
状态：产品与技术设计，等待实现评审

## 1. 目标

平台管理必须独立于 SEM、SEO、GEO。超级管理员从全局入口统一管理客户、模块订阅、登录账号、角色和权限；三个业务模块只管理自己的业务对象。

现状已有 `/api/v1/admin/customers*`、`/api/v1/users`、`/api/v1/roles` 以及两个前端页面，但入口仍位于 SEM 主壳的“系统设置”，客户与账号流程被拆开，登录管理员角色还可能因缺少 `settings.customers=edit` 而看不到客户模块管理。

## 2. 信息架构

全局右上角增加独立齿轮入口 **平台管理**，路由使用独立命名空间：

- `/platform/customers`：客户与业务
- `/platform/accounts`：账号
- `/platform/roles`：角色与权限
- `/platform/audit`：操作记录（第二阶段）

原 `/settings/customers`、`/settings/accounts` 保留兼容重定向，页面和导航不再归入 SEM 工作流。

### 客户与业务

客户列表以客户为主对象，每行显示：客户名称、状态、已开通模块、到期时间、账号数、最近登录、数据接入状态和需要处理的事项。

客户详情抽屉包含：

1. 基本信息：名称、行业、品牌词、业务说明。
2. 模块订阅：SEM/SEO/GEO 独立开关，状态为未开通、试用、正式、停用、已过期；明确开通时间和到期时间。
3. 登录账号：该客户可用账号、角色、状态、最近登录、重置密码和停用操作。
4. 数据接入：SEM 推广账户、SEO 站点、GEO 项目的只读状态摘要；具体业务配置跳转到相应模块。
5. 操作记录：谁在何时修改了模块、账号或权限。

模块操作必须二次确认并展示影响，例如“停用 GEO 后客户将无法进入 GEO，历史数据保留”。不得物理删除历史业务或审计数据。

### 账号

账号页支持按客户、角色、状态搜索，显示用户名、显示名、客户范围、角色、启用状态、最近登录和创建时间。

允许创建、停用、恢复、调整客户范围、调整角色、发起密码重置和注销全部会话。禁止显示、导出或恢复现有密码明文。

### 角色与权限

权限矩阵按产品域分组：平台管理、获客工作台、SEM、SEO、GEO。每项使用无权限、查看、编辑三级。平台管理权限与业务模块权限分开。

内置管理员角色必须始终保留 `settings.accounts=edit` 和 `settings.customers=edit`，后端与前端同时防止自锁。租户绑定账号不能获得跨客户模块管理能力。

## 3. 权限边界

- `settings.customers=edit`：客户资料与模块订阅；同时要求账号未绑定单一租户。
- `settings.accounts=edit`：账号和角色管理。
- 只具备其中一项时，仅显示对应页面；具备两项时显示完整平台管理中心。
- API Key 超级管理员继续用于受控脚本和运维，不作为普通前端登录身份。
- 所有写请求继续由后端鉴权，前端隐藏按钮不能代替权限控制。
- 客户、模块、账号、角色写操作必须记录操作者、时间、旧值、新值、原因和请求标识。

## 4. 密码与会话安全

平台管理员可以“重置密码”，不能“查看密码”。目标流程：

1. 邀请链接或一次性临时密码通过既有安全渠道交付。
2. 临时凭据首次登录必须修改。
3. 重置密码后旧会话全部失效。
4. 页面只显示“已设置、最后修改时间、是否必须重置”，永不回显密码。
5. 管理员不能停用自己，也不能移除自己最后一个平台管理权限。

当前接口可以先保留人工设置新密码，但“首次强制修改”和“注销全部会话”需要后续增加 `must_change_password`、`password_changed_at`/会话版本等服务端能力，并单独进行数据库评审。

## 5. 第一阶段实现（不迁移数据库）

1. 新增独立平台管理壳和全局齿轮入口。
2. 复用并重组 `CustomerModulesView.vue`、`AccountsRolesView.vue`。
3. 将旧设置路由重定向到 `/platform/*`。
4. 修复内置管理员权限不变量：同时保留客户模块和账号角色两项编辑权。
5. 客户详情中合并模块订阅和客户账号视图。
6. 模块开通继续调用 `PUT /api/v1/admin/customers/{id}/modules/{code}`；账号、角色继续使用现有正式接口。
7. 增加前后端权限组合测试、单租户账号隔离测试和自锁保护测试。

## 6. 第二阶段

- 邀请与强制改密、会话统一失效。
- 追加式平台审计日志和审计查询页。
- 一个内部账号绑定多个指定客户；当前模型只支持“单一客户”或“全部客户”，该改动需要独立数据模型与迁移评审。
- 批量开通/续期和到期提醒。

## 7. 验收标准

1. 超级管理员登录后始终能看到全局“平台管理”入口。
2. 平台管理不出现在 SEM、SEO 或 GEO 的业务导航组内。
3. 管理员可在一个客户详情中查看并修改三个模块状态与期限。
4. 管理员可创建、停用和重置客户账号，配置角色权限，但无法查看原密码。
5. 租户绑定账号不能访问其他客户或平台级客户模块写接口。
6. 修改模块后 `/api/v1/auth/modules` 与工作台模块显示一致。
7. 停用/过期模块隐藏且不计入工作台待办；历史数据保留。
8. 任何权限不足、数据为空、模块未开通必须显示为不同状态。
9. 旧 `/settings/*` 地址安全跳转到新入口，不产生死链。
10. 所有写操作失败时保留原状态并显示明确原因。
