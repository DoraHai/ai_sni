# GEO 真人验收需求

## 本轮目标与分工

需要一位有当前测试客户权限的人，完成真实内容确认、客户审核和测试渠道后台核对。客户可以审核自己提交的稿件，只需一次人工审核，不需要第二位审核人员。

开发侧负责自动化回归、数据库并发、超时故障注入、跨客户接口隔离、日志排查与修复。不要通过关闭浏览器网络、重复对正式渠道发送、虚构回填网址来制造超时或恢复用例。这些故障场景由开发侧在隔离环境实施。

上轮结果按用户报告留档：客户隔离通过；母稿生成及真实发布受阻；版本、并发、恢复与发布后改善尚未实业务验收。测试账号、业务、提问及任务已清理，不能继续使用旧任务 ID；没有公开发布残留。基线“—”是未知，提及 0 需要同时提供有效样本数才可解释。

## 开测前必须准备

1. 可登录 GEO 的客户账号，明确本轮测试客户 ID。确认进入测试客户后再创建数据。
2. 一个专用测试渠道账号或测试站，允许真实创建、查看及删除测试文章。把凭据直接配置在 GEO 渠道设置里，不发到聊天或测试报告。页面核验需要服务端能读取正文；仅后台可见的草稿或登录页不算可核验发布页。
3. 至少三条**真实、有来源、已核验、有效且未归档**的事实卡，绑定到本篇任务。建议提供产品/服务说明、适用范围与限制、可核实的参数或案例。每条包含事实原文、来源名称，能提供时附来源链接/文件、版本日期。三条事实可以来自同一真实文档，不要求凑三个网站。不能为了开测把编造内容标为已核验。
4. 完整创作要求：行业、受众、意图、内容类型、CTA。确定稿件可发布的范围和测试文章清理方式。

测试发布站可以用于验证发布链路；它不能证明真实品牌的 AI 可见度提升。效果验收需另用获准发布的真实内容及可比样本。

## 真人必跑：先完成这四项

| 用例 | 操作 | 通过标准 |
|---|---|---|
| H1 资料与母稿 | 新建测试任务，绑定合格事实并填写创作要求，生成母稿。核对页面显示的资料排除原因及正文事实。 | 至少三条资料符合条件；能生成稿件；正文没有添加无法核实的事实。若受阻，记录事实 ID 与错误原文，先停止后续发布测试。 |
| H2 一次客户审核与版本 | 技术检查通过后，确认待审状态不能发布；客户审核一次。随后修改并保存母稿，检查原审核/旧渠道稿不能直接用于新版发布。重新生成渠道稿并确认当前保存版本。 | 未审不能发；改稿后不能沿用旧审核；当前母稿和渠道稿版本一致；无需另找第二位审核人员。界面没有可点按钮时记录禁用提示即可。 |
| H3 真发布与防重核对 | 客户确认后向专用测试渠道发布一次。记录任务/稿件/发布记录 ID，在渠道后台查找文章。刷新 GEO；若界面允许对完全相同的稿件和账号重复执行，核对返回原结果。 | 渠道后台仅一篇，GEO 记录指向同一篇；网页正文与审核稿相符。不要改正文后重发来测试防重，那属于新的发布请求。 |
| H4 发布页核验与监测 | 打开分发页“发布后监测”，点击重新检查；查看检查时间与正文匹配状态。 | 服务端实际抓取后显示正文匹配；登录页、错误文章或空壳页不能被当作匹配。重复点击五分钟内允许返回原检查结果。 |

H1–H4 预计操作约 30–60 分钟，不含资料准备、生成排队和渠道授权审核时间。任一前置条件失败，后续用例记录“受阻”，不要记录“通过”。

## 配合开发侧补验

- **跨诊断合并：**对同一个测试页面的同一问题诊断两次并生成工单，确认复用原单，负责人、截止日期、原始证据仍在；带不同查询参数的页面不得仅因路径相同而误合并。
- **发布异常恢复：**仅在可控测试站协同修改/恢复测试页。正常每 24 小时复查，异常每 1 小时重试，连续两次异常生成跟进工单；恢复正文并重新检查后才关闭。手动检查相隔至少五分钟，不能靠人工打勾关闭。抓取失败只表示尚不可核实，不等于确认下线。
- **超时/重试/恢复与同时发送：**开发侧先做隔离故障注入；需要渠道侧配合时，提供同一篇测试文章的后台数量、URL、时间和结果即可。unknown/sending 时先核对后台，不盲目重发。
- **客户隔离：**在两个授权测试客户间切换，确认文章、事实、工单、发布记录不串；不使用正式客户数据作编辑或删除测试。
- **效果闭环：**开发侧核对同题、同引擎、同模型、同采样次数和原始快照。基线与后测使用上海时区完整自然周（周一零点至下一周一零点），后测周必须完整位于真实发布核验之后。缺样本应待观察，不能填 0；未达目标应生成复盘工作；达标仍需原任务真实指标验收。不要为了当天通过而补造历史数据。
