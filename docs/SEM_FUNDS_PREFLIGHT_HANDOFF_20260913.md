# SEM 单条资金动作即时预检交接

## 基线与范围

- 开发基线：`origin/main` `d8eb28605541c8a2f9615caeb634566ab8383c8b`。
- 本轮只处理账户日预算、计划日预算和单元出价三个单条资金动作。
- 不修改批量动作、非资金动作、百度服务端写回实现、全局 dry-run、数据库结构或其他模块。
- 验证只使用前端 mock 和静态契约，不连接生产数据库，不调用百度接口，不部署。

## 已完成

三个入口都在最终确认框出现前重新读取 `/api/v1/writeback/mode`，并按当前客户、可信
`baidu_account_id` 和精确动作 scope 运行失败关闭的账户级预检：

| 入口 | 动作 scope | 资金说明 |
| --- | --- | --- |
| 账户日预算 | `account_budget` | 解释演练/真实、当日额度、一次性资金确认与服务端二次复核 |
| 计划日预算 | `campaign_budget` | 同上；输入金额后才执行预检，再显示最终确认 |
| 单元出价 | `adgroup_bid` | 同上，并解释账户策略中的单次调价幅度上限 |

预算动作不会误显示“单次调价上限”；该字段只用于关键词和单元调价。任何缺失、重复、畸形、
跨客户或跨账户策略都禁止提交。预检只用于解释当前快照，不预留额度；写接口继续由服务端在事务内
复核账户授权、动作 scope、额度、资金确认和参数指纹。

单元出价方法现在显式检查 `manage.adgroups` 编辑权限和行内可信账户是否 active。三个入口均在
预检返回后、最终确认后复核请求 generation；撤权、切客户、切账户或账户停用会使当前动作失效，
不会继续显示最终确认或提交写请求。

## 验证与边界

- `npm run test:sem-classic-components`：覆盖账户切换、权限撤销、账户停用发生在预检期间时不确认、
  不写入，以及既有 SEM 页面上下文回归。
- `npm run test:sem-ui-contracts`：覆盖三个精确 scope、资金确认/额度说明、预算与调价限制文案边界，
  并锁定 preflight 必须先于对应写 API。
- `npm run build`：通过（2411 个模块；仅保留既有 chunk size 与共享依赖注释警告）。
- `npm run verify:sem-build`：通过（检查 109 个 JS 产物，首屏 JS 397749 bytes）。
- `git diff --check`：通过。

本地测试不会证明生产账户当前开放了这些 scope。生产是否允许真实执行仍以受控身份即时读取的
账户策略、环境总闸和服务端提交时复核为准。
