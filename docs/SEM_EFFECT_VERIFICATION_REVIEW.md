# SEM 原有效果验证整改与后续事项

日期：2026-09-05。基线：main `d47751ca6ba83173320c589cfd9d9b30b793b0fe`。
范围仅为原有调价/预算效果验证链路，不代表全部 SEM 模块已穷尽审查。
指标看板暂缓；不涉及 SEO/GEO、资金写回执行逻辑、Schema 或部署。

## 本次修复

- 预算效果仅纳入 `status=success AND dry_run=false` 的台账；演练、待确认、
  待对账及失败不作为实际调整参与效果评估。原始台账不删除。
- 关键词按租户、百度账户、词名和操作记录中已有的计划/单元定位；不再按展现量
  选择同名词。缺账户或存在歧义时返回 unmatched，不猜测归属。
- 关键词报表和最新数据日均限定到目标账户、关键词、计划、单元。
  预算报表和最新数据日限定到账户，以及适用的计划。
- 预算日均消费按实际有报表的日期数计算；缺报不当作零消费。
  缺调前数据时不能标为样本就绪。
- 未唯一匹配或样本不足时不调用 AI。AI 缓存绑定身份、调整值及当次效果数据，
  数据变化后旧结论失效；历史无依据缓存不展示、不删除。
  使用现有 `ai_reason` 文本字段保存带版本的缓存封装，接口仍只返回人可读理由。
  原人工审核记录保持不变，不能把人工“已验证”自动解释为因果效果已经证实。
- 单条 AI 入口拒绝非关键词出价操作；列表和单条重算采用一致的归属规则。

## 继续整改（已实现，发布另行审核）

1. **人工验证证据**：先按租户查真实关键词操作/真实成功预算台账；不存在返回 404。
   达成/未达成必须样本 ready 且有至少 4 字核对依据，服务器重算并保存当时指标。
   观察保留 pending；重新打开清空 verdict/verified_at，不销毁已有证据。
   证据使用现有 note 文本字段的带版本 JSON 封装，API 分开返回 note 与 evidence。
   人工审核 upsert 防止同记录并发创建冲突；不更改百度写回审批机制。
   前端展示历史指标依据；旧人工标记明确提示“无指标快照”，不假装自动补齐。
2. **完整分页**：先在数据库按审核状态筛选，再按时间/id 稳定排序、offset/limit 分页；
   返回日期范围总数、各状态计数、当前筛选总数及 has_more。前端每页 50 条，切换客户、
   日期、状态及保存审核后回第一页。并发其他用户修改状态时应刷新列表，不是冻结历史快照。
   同时补上原先遗漏的 GET /api/v1/adjustment-verify/budget 路由。
3. **独立效果窗口**：以北京时间完整自然日报表为口径，从调整次日开始，截止最新已完成
   报表日，且不得包含下一次同对象调整当天。关键词账户/计划/单元隔离，缺维度的同名
   后续调整保守截断。预算按相同账户与预算对象隔离，仅真实成功调整构成确定的后续边界。
   预算 executed_at 为代码写入的 UTC，转换北京时间；历史缺执行时间时回退 created_at
   （历史数据库本地时间口径）。元数据和页面明确说明窗口、时区及非因果性质。
   连续调整不足 3 个完整报表日不能作达成/未达成结论。

以上是已有功能正确性和可用性的改进，不新建指标看板，也不扩大真实回写权限。
