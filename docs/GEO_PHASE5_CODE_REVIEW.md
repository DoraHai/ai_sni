# GEO 第五批：代码检查与证据一致性修复

日期：2026-09-05。检查范围为本地 GEO 前四批改动及相关调用路径；未提交、推送或部署。

## 已修复问题

1. **机会展示与任务创建的证据可能不一致。** 之前只检查快照 ID 和当前资格，原文或引用改变但仍满足资格时，会静默使用新依据。现在机会返回 evidence_version，建任务必传并在服务器重新计算比较；不一致返回 409，要求刷新。版本覆盖同组全部可用样本的原文、引擎、时间、来源、方法备注、提及、引用和准确性，以及问题文本、自有域配置。版本按 ID 排序，重复行或数据库返回顺序不影响结果。它是乐观一致性校验，不是签名或不可篡改证明。

2. **快照页面内切换链接可能继续使用旧问题筛选。** 新增对 prompt_id / snapshot_id 路由变化的响应，更新筛选、清空旧证据并重新加载；目标不在当前列表时给出提示，不继续展示上一条证据。

3. **冲突的方法标记可能被当作普通历史样本。** 多个不同 method 标记现在明确记为 conflicting，指标判定为待复核；冲突 analysis 标记也进入待复核状态。

## 本次检查结论

- 复查了机会筛选、任务创建校验、任务来源持久化、客户隔离、快照跳转、指标标记及异步作业锁的相关实现。
- 证据版本校验仅在新建任务前执行；已有任务仍直接打开，不修改其来源。当前客户端和新增接口需一起更新，旧客户端缺少版本字段时会被请求校验拒绝。
- 新增接口仍允许基于明确提交的样本集合建任务；版本不证明该集合涵盖整个观察窗口，也不防止有权限的调用者自行选择样本。
- 数据库行锁只覆盖本建任务入口，旧建任务入口没有统一锁协议；跨入口并发唯一性仍未保证。
- 作业 advisory lock 要求固定会话连接。实库并发、连接中断和连接池压力尚未验证；不能将模拟测试视为这些场景的验收。
- 旧信源卡片、日聚合及其他旧指标路径仍未全面统一；新机会区与旧卡片应按各自说明解读。
- 本批未改其他模块、共享数据库模型或迁移。
