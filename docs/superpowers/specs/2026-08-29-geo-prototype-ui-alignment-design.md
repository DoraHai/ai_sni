# GEO 新版原型 UI 对齐设计

## 目标

以 `frontend/public/deal-sniper-prototype/geo/` 中 2026-08-26 更新的静态原型为 UI 与信息架构基准，重构现有 Vue GEO 工作台，使侧栏、页面名称、页面拆分、首屏结构、筛选区、表格字段和主要操作位置与原型一致，同时继续使用现有后端 API、租户登录和真实数据。

## 非目标

- 不重写后端接口、数据库模型或鉴权体系。
- 不恢复每页 `tenant_id`、API Key 和“保存上下文”控件；当前登录客户选择器继续作为真实产品环境的上下文入口。
- 不删除当前已有但原型未展示的后端能力。
- 不新增审批流、多租户协作、CRM、预算、投放项目管理等原型范围外能力。
- 不进行与 GEO 原型对齐无关的 SEM、SEO 或诊断中心重构。

## 设计原则

1. 原型决定页面边界、导航顺序、标题、首屏结构和主要控件。
2. 当前后端决定数据来源和可执行行为；原型中的假数据不进入 Vue 页面。
3. 原型没有但当前已上线的能力不删除，优先收进“更多”、二级入口或设置页。
4. 原型中存在而后端暂不支持的操作以清晰禁用态或空态呈现，不制造成功反馈。
5. 页面保持当前 Element Plus 和 Vue 3 技术栈，不引入第二套 UI 框架。

## 信息架构

侧栏按原型恢复为以下顺序：

- 数据看板
  - GEO 概览
  - AI 可见度
- 智能监测
  - 优化意图词
  - 竞品分析
  - 评价分析
  - AI 引用次数
  - 事实库 / 信源
- 内容与信源
  - 优化文章
  - 媒体 / 信源策略
  - 验收工单
  - 分发平台
  - 发布渠道配置
- 设置
  - AI 能力配置
  - 引擎

当前“品牌资料”和“渠道成稿提示词”不删除，改为从相关页面的次级入口进入，不占用原型主侧栏。`采集与判断` 不再作为独立信息架构概念；其登记与快照能力回收到 AI 可见度页面。

| 媒体 / 信源策略 | `/geo/media` | 重排现有信源策略页 |

旧路由继续重定向到新 canonical 路由，避免已有书签和后端深链失效。

## 页面设计

### 数据看板

GEO 概览恢复“可见度期次对比”和最短操作路径作为首屏。当前 KPI、趋势、SOV、高曝光提问和引用来源保留在对比区块之后。AI 可见度把回答登记、AI 探测、人工标注、保存快照和快照列表放回同一页；当前经营分析卡片折叠到快照列表之后。

### 智能监测

优化意图词以候选拉取、勾选入库、CSV 导入和机会问题列表为主，当前业务/关键词/提问三级管理通过次级入口保留。竞品分析首屏恢复竞品、出现次数、关联提问、引擎和最近观测表格，热力图和领先场景移到下方。评价分析独立展示位置/情感分布和最近快照。AI 引用次数恢复域名聚合明细。事实库恢复来源、作者、可信度和过期日等信息，并提供导入、创建和核验入口。

### 内容与信源

优化文章恢复紧凑任务表，表格包含 ID、标题/问题、流水线、状态、门禁和更新时间；当前 GEO 写作说明降为可折叠帮助。在线编辑器按“Brief → 事实绑定 → 母稿 → 渠道适配 → 检查”纵向组织，保留当前富文本编辑能力，并把高级审校与批量操作收进“更多”。媒体/信源策略恢复按问题组的推荐表和布局清单。验收工单提供列表、批量重抓、批量验收和创建媒体工单入口；不支持的动作必须显示真实原因。分发平台面向单个任务的渠道稿、推送和回填；发布渠道配置只负责渠道与账号。

### 设置

AI 能力配置保持现有真实密钥与模型配置逻辑，结构对齐原型。引擎页以启用、key、展示名、排序和备注表格为主；当前接口配置和巡检频率放在可展开的高级设置区。

## 共享 UI 组件

新增或复用以下小型组件，避免复制静态 HTML：

- `GeoPrototypePageHeader`：标题、副标题、主次操作。
- `GeoPrototypeToolbar`：筛选项、搜索和刷新。
- `GeoPrototypeTableSection`：区块标题、表格、分页和空态。
- `GeoPrototypeContextNotice`：未登录、未选客户、缺少配置时的统一提示。

组件只负责布局，不持有业务请求。每个页面继续通过现有 API 模块和组合式函数管理数据。

## 数据与错误处理

- 所有请求继续带当前 `tenant_id`，不在 UI 暴露原型的手工 tenant 输入。
- 原型字段无法由现有 API 提供时显示 `—`，不推导假值。
- 页面首次加载失败时保留页面框架，区块内显示错误和重试按钮。
- 批量、推送、核验和删除操作沿用现有确认与错误提示。
- 旧页面深链通过路由重定向保留查询参数和任务 ID。

## 测试策略

1. 扩展导航测试，断言原型页面名称、顺序和 canonical 路由。
2. 增加路由测试，覆盖新页面、旧路由重定向及任务编辑器参数。
3. 为共享页面组件增加结构测试，固定标题、工具栏和空态契约。
4. 为每批页面增加轻量静态契约测试，断言原型关键按钮和表头存在。
5. 运行现有 `node --test tests/*.test.mjs`。
6. 运行 `npm run build`，确保 Vue 模板和路由懒加载可编译。
7. 启动本地服务，逐页验证 15 个 canonical 路由无白屏、无控制台错误，并抽查真实客户数据。

## 实施顺序

1. 建立共享组件、导航和 canonical 路由，补齐空白页面骨架。
2. 完成数据看板和智能监测页面。
3. 完成内容、编辑器、信源、验收和分发页面。
4. 完成设置页面，收纳当前原型外能力。
5. 执行完整测试、构建和浏览器逐页验收。

## 验收标准

- 侧栏名称、分组、顺序与新版 GEO 原型一致。
- 15 个原型页面均有可访问的 canonical Vue 路由。
- 每页 H1、首屏主区块、主要按钮和表格字段与原型一致。
- 当前登录客户、真实数据、生成、保存、检查、推送和回填能力不因改版失效。
- 原型外能力不再干扰主页面，但仍可通过次级入口访问。
- 前端测试全部通过，生产构建成功。
