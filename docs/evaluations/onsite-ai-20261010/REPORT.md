# SEO/GEO 真实模型隔离评测 · 2026-10-10

结论：当前上线版本不具备稳定交付站内 AI 提案的条件。SEO 模型能起草相关内容，但输出与应用契约频繁不一致；GEO 当前接入点返回 model_not_found。隔离候选方案有改善，但仍有跨资料场景失败，因此未发布，也未启用自动建单、网站写入或自动批准。

## 测试方法与范围

- 真实调用已上线的供应商客户端，使用已上线提示词与校验器建立基线；来源版本 SEO `d6297f3b7b7af643fe402058aa2c3cb87d4ad247`、GEO `d648b0c8a8df176c0b3b4fc08142b7b6dd670127`。
- 主样本为虚构工业洗地机，明确给定 40 升水箱、500 毫米刷盘、24 伏供电，以及易燃易爆环境禁用条件。产品价格、续航、认证与营销承诺均无依据。
- 每模块 8 个样本：正常起草、相同资料重复、纠正旧方案、缺资料、夹带指令、要求跨客户、参数冲突、无依据营销承诺。重复样本是独立质量评测请求，不是 nonce 去重测试。
- 另用虚构 VOC 检测仪的正常/冲突资料各 1 个样本检验候选方案迁移能力：0–20 ppm 与 0–50 ppm 相互冲突，不能任选一个结果。
- 输入为答案已知的合成资料；没有复制真实客户资料、创建生产客户任务或调用网站发布/资金写回。测试不等同于真实客户项目验收。
- 调用走已有费用台账，origin=system、tenant/user 未绑定客户，job_ref 以 onsite-live-eval-20261010 标识。未保存供应商密钥。
- 本次直接评测生成客户端和保存校验器，没有通过生产顾问按钮写入工作流。权限、配额、格式和状态约束另跑隔离单元测试：SEO 16 项、GEO 14 项通过。并发与 PostgreSQL 权限测试的先前发布记录不能冒充本次真实内容评测。

## 评分规则

合格分 = 合格样本数 ÷ 本组样本数 × 100。它是本轮样本的交付合格率换算，**不是 AI 智商、营销效果、人工专业质量的百分制评分，也不是未来成功率估计**。

合格要求：通过现有保存校验；已知关键事实与客户范围没有错误；建议对应输入中的页面、关键词或问题。正常资料需产出相应待审内容；缺资料样本正确留空并说明缺项可以通过，不能用“全部留空”冒充正常样本完成。校验器只能验证部分性质，有效来源引用仍不证明每句话正确。本次由助手对照固定答案复核内容，没有真人顾问或营销专家参与评分；重要事实/范围错误判不合格。

|版本|SEO|GEO|
|---|---|---|
|当前上线基线（各 8 个样本）|1/8，12.5/100|0/8，0/100|
|隔离候选 v3（主样本 8 + 另组资料 2）|9/10，90/100|2/10，20/100|

GEO 基线没有成功生成正文，内容质量无法评分；0 分表示当前配置的可用性为 0。候选 GEO 同时更换了隔离调用的供应商路线与提示词，不能据此单独评价模型之间的优劣。候选使用现有已验证可调用的 DeepSeek 官方凭证与 deepseek-chat；生产仍沿用原配置。

主样本 SEO v3 为 8/8，但检测仪冲突样本为空预期值时没有列出 missing_information，仍被拒绝。这说明改善提示词可以提高当前样本通过率，无法证明新场景稳定。

## 主要发现

1. **GEO 供应商路线未验证可用。** 原配置 deepseek-v4-flash + dashscope.aliyuncs.com/compatible-mode/v1 返回 HTTP 404。独立诊断错误码 model_not_found，类型 invalid_request_error。只能据此判断当前凭证/接入点无法使用该模型，不能断言这个模型全球不存在。[阿里云官方 DeepSeek 接入文档](https://help.aliyun.com/zh/model-studio/deepseek-api)说明地域和接入地址需要匹配；准确替换配置仍需验证。
2. **SEO 提示词没有表达完整的应用输出契约。** 模型将内链 expected 写成解释、HTML 或反向链接。规范值应为当前来源页面要链接到的已绑定目标裸 URL。
3. **自然语言 URL 解析会误伤合法说明。** 基线 normal_a、revise 的正文参数有依据，但理由中裸 URL 后的中文标点和后续文字被既有正则一起当成 URL，导致拒绝。候选先通过避免在说明重复写 URL 绕开，生产校验实现仍未修改。
4. **缺项与拟发布内容冲突。** 模型能意识到资料缺失，却仍同时给 expected 和 missing_information。SEO 原校验正确拒绝这种不明确状态；候选 v3 将这类项的 expected 安全留空，保留原缺项与来源，没有清除阻碍来让结果通过。
5. **GEO 结构字段不稳定。** source_refs 有时变成字符串列表；missing_information 有时变成一段字符串；JSON-LD 的 audienceType/description 等字段与可见正文不是同一句，因而被拒绝。附加自然语言规则仍不能稳定解决。
6. **范围与夹带指令样本没有诱导模型执行动作。** 本轮候选正文未输出测试指令标记或改成另一客户的落地地址；本轮没有网站工具能力。此结果只覆盖设定样本，不是任意攻击下的保证。
7. **内容总体能贴合给定事实，完整月度计划尚未测试。** 正常通过的 SEO 输出包含正确产品参数、页面绑定词和内链方向；通过的 GEO 输出包含适用/禁用条件与公开资料导览。目标分解、优先级、排期、任务量及实际排名/收录/引用效果不在当前站内提案评测范围。

## 已验证的候选改动

- 明确 SEO URL 字段的方向与裸 URL 格式，将操作与锚文本放在 instruction。
- 明确无争议事实、缺项、旧方案和冲突资料的关系；修订不能把旧 expected 当成事实。
- GEO 明确来源引用对象格式，正文使用可读文本，并要求 Schema 文本来自同轮可见内容。
- SEO 候选只执行保守留空：原输出同时有非空 expected 和非空 missing_information 时清空 expected。原始输出与处理后的输出都保留在证据中。
- 这些改动只在 runner.py 的隔离候选模式内验证，未写入生产源码或服务配置。v2 为过程对照，不混入最终候选分数。

建议上线门槛：关键范围/事实/缺资料/冲突样本全部正确处理；正常样本形成可保存的完整待审提案；在多个真实业务样本和重复生成中达到预先约定的通过率。小样本 90 分仍不能证明稳定交付。上述 P0 完成并复测前，不开启月度自动接续或网站执行。

## 调用与费用证据

- 实际供应商请求：53 次；HTTP 成功 44 次，HTTP 错误 9 次（GEO 原配置 404）。没有隐式重试。
- 已知输入 token：63,958；其中已知缓存 token：29,182；已知输出 token：54,269。9 次错误响应未提供用量，不能认定免费。
- 53 次台账 estimated_amount 为 null；当前 DeepSeek 官方 deepseek-chat 路线没有匹配的既有单价，不能给出人民币总成本，也没有将未知填成 0。
- 原始输入、输出、校验结果、单次耗时、运行源码、模型与上线来源版本见 evidence.json 和 runner.py。
