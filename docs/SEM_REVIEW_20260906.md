## 确认并修复的问题

1. **审批目标 ID 精度丢失**：`writeback_approval._positive_id` 通过 float 转换所有 ID，
   9007199254740993 会变成 9007199254740992，两个目标产生同一归一化指纹；
   字符串 `7.0000000000000000001` 也会被当成整数。测试在修复前实际失败。
   改为 Decimal 无损解析、先校验有界整数再转换；不接受不安全的大浮点 ID。
   普通整数/字符串保持兼容，最大 signed bigint 可保留。未改变金额、实名、TTL、
   approver、幂等锁或消费规则。不证明线上已有这么大的目标 ID 或已发生错误执行。
   如历史确认包含被错误舍入的大 ID，新版本可能拒绝，需重新确认；不修改历史记录。

2. **徽章请求权限与故障互相牵连**：原来始终同时请求告警和拓词，并用 Promise.all。
   只有告警查看权限的账号也请求拓词；一个失败就清空另一个正常结果。
   修复前回归测试证明发出了无权限请求。现在按菜单权限请求，各自接收成功结果。
   保留租户身份隔离及过期结果检查，不改变后端鉴权。

3. **旧客户列表错误覆盖新状态**：成功分支校验请求代次，但失败分支没有。
   新请求成功后，旧请求晚到的失败仍可设置全局错误横幅。
   失败分支也校验请求代次和模块范围；测试覆盖旧失败晚于新成功的场景。
