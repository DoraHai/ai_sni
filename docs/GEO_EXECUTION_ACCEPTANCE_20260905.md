# GEO 执行验收与严格审查

已关联内容的执行待办，在人工验收通过前，服务端重新核对七步进度：基线、内容任务、创作要求与事实、当前正文、有效发布地址、当前版本复测、足量同引擎对比。缺项返回 409 并列出待处理步骤。未关联内容的采集、核验待办保留原人工验收流程。

通过后，在 progress.acceptance 保留检查时间、内容任务、正文版本记录、步骤与人工结论。回执表示检查当时的状态，不证明 GEO 效果提升，也不是持续有效性监控。发布地址格式和发布记录通过检查，不代表系统已访问并核实外部页面正文。

审查修复：
- 已完成待办拒绝修改执行关联或重复覆盖验收回执，需先重新打开。
- 关联请求携带页面加载时的正文版本；若服务端读取的版本不同，拒绝旧页面提交。旧 API 调用者省略此字段仍保持兼容。
- 仅保存基线时也校验样本时间，不能将正文之后的采样作为修改前证据。
- 空白、非 HTTP(S) 地址不能满足发布步骤。
- 执行计划加载期间与已验收状态下禁用证据编辑；子面板保存期间同步锁住父级状态操作和筛选。

验证：567 项后端测试、59 项前端测试通过，GEO 独立前端生产构建通过。覆盖每个验收缺项、旧版本、已完成记录、跨客户隔离、错误证据、发布地址、父子操作互斥等。测试使用隔离配置和模拟请求，未调用真实模型、未写入客户发布数据。

边界：验收记录是版本化检查回执；不锁住后续独立的文章修改，也不会自动将历史验收撤销。当前没有对整个编辑与发布系统实施全局串行事务。

无数据库结构变更；发布仅走 GEO 独立流程。
