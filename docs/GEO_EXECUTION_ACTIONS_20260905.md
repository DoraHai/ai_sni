# GEO 执行能力增强

## 差距与产品参考

现有执行待办需要人工找到内容任务、抄写快照编号；状态记录不能直接说明如何推进。此次将待办与实际工作入口、材料缺口、内容版本及可选证据连接。

调研只使用厂商公开说明，不代表已购买实测：

- [Peec Actions](https://peec.ai/blog/introducing-actions)：按信源与竞争缺口整理优先行动，区分自有内容和第三方媒体，并提供保存、完成、忽略操作。
- [Scrunch Signals](https://helpcenter.scrunchai.com/en/articles/15879296-understanding-the-signals-tab)：将回答信号指向具体页面优化、竞争缺口和内容机会。
- [Scrunch 内容优化](https://scrunch.com/how-tos/how-to-optimize-content-for-ai-search/)：从问题与页面匹配出发提出具体内容优化建议。

本次借鉴“由机会直接推进具体工作”的设计，不把同行商业宣传当作效果保证。

## 已实现

1. 待办内准备内容：同题优先关联已有内容任务；不存在时创建草稿，带入目标问题、待办要求、验收条件与内容结构要求，同时保留可用修改前样本。不会覆盖已有正文或自动调用模型。
2. 执行步骤：根据保存的基线、内容任务、可生成事实、Brief、当前文章版本、该版本发布记录及复测关联显示 7 个环节。新版本出现后，旧版本复测不计作当前版本已完成。
3. 自动查找证据：仅查当前客户同一问题，按当前内容版本时间划分修改前与复测，显示原文摘要、引擎、时间、品牌判读及原始记录链接。可逐条勾选或选择每个引擎最近 3 条候选；不再抄编号。
4. 缺口提示：显示每引擎两侧还差多少样本，提供同题采样和内容编辑入口。每侧仅检查最近 100 条，界面说明截断和不合格样本排除情况。
5. 保存稳定性：相同工单刷新不再误判为客户切换；过期计划请求不能覆盖新的选择，切换客户后旧准备结果不得写回。

## 验收

- 后端 GEO 全量与 metric_service：549 项通过；前端 GEO：52 项通过。
- 独立 GEO 生产构建通过，保留已有包体积提示。
- 本地浏览器（内存 API，无生产连接）验证加入待办、直接准备内容并保留基线、选择候选样本、填写修改说明、保存后执行步骤保持可见。
- 后端测试覆盖重复准备复用任务、不覆盖已有 Brief、已完成工单拒绝创建、跨客户访问拒绝和内容版本变化后的复测失效。
- 本次复用既有字段，无数据库迁移。不自动发起真实模型采样、客户内容发布或第三方外联；这些仍由执行者在对应功能中发起。数据库测试未进行 PostgreSQL 并发压测。
