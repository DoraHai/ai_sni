## 1. 结构对账：管理员在单独获准后执行，当前无需操作

文件：`ops/sem-task-migration/preflight-readonly.psql`。
用管理员确认属于 SEM 实际数据库的已认证 psql 会话执行该文件（不用连接串作命令参数）。
禁止把生产密码、完整 .env、数据库 URL、恢复码粘贴进报告。
脚本 REPEATABLE READ + READ ONLY，同一快照读版本及 public 结构，最终 ROLLBACK；
只读客户表元数据，不读取客户行。错误立即中断，断开会话回滚，不改为宽松模式重试。
成功必须有完整 JSON、ROLLBACK 和退出码 0，不能拿部分输出放行。

共享迁移负责人逐项签核：

- 数据库/地址/端口/角色与服务实际连接目标一致（不能仅凭命名认定）。
- 非系统 Schema 中只有 public 的一张真实 alembic_version 表，单行 0094；
  public.tenants.id 为 bigint、非空且单列主键。任何差异停止。
- sem_tasks、其序列、主键名、两个索引名全部不存在；不可 IF NOT EXISTS 跳过冲突。
- 对应执行角色具备 schema USAGE/CREATE、tenants REFERENCES、版本表 SELECT/UPDATE。
  权限报告不证明全部运行权限；新表/序列 owner、应用 SELECT/INSERT/UPDATE/DELETE 及序列
  USAGE 必须在本地按批准角色演练。角色不同则授权方案单独审核，不在迁移里自动 GRANT。
- 对 public 全部所列关系的字段、类型、空值、默认值指纹、约束、索引进行逐项对账；
  任何差异注明来源、影响及批准人，不能只比 revision 字符串或主表数量。

此脚本不是完整 pg_dump：函数、扩展、触发器、策略、ACL、分区边界/视图定义等未覆盖。
默认表达式仅给 MD5 指纹以避免输出可能的常量；它是差异提示，不是安全摘要。
若这些对象影响迁移或客户删除，负责人须补充限定范围的结构核验。
现有最小本地 fixture 不能充当完整生产 0094 基线；不能自动宣称“全库一致”。

## 2. 正式入口必须实现的契约（实现前先审定身份与证据来源）

入口与应用发布分离，部署后端不得触发它。不得用 main 根目录 Alembic 配置或生产 release
目录，不把历史迁移复制进应用后执行 upgrade head。须另有专用批准配置和只读产物目录。

正式入口必须绑定以下审批材料；缺一项拒绝，不能仅传一个 confirmation 字符串放行：

1. 变更单 ID、执行人、验收负责人、UTC 有效窗口及批准记录。
2. 审核提交完整 SHA、源包所有文件摘要、目标 0095 与唯一父节点 0094；
   构建必须拒绝脏工作区，候选/env/工具均取批准 Git blob，审核制品整体 SHA-256。
3. 确认过的数据库身份、执行角色、固定 public Schema、获审结构快照及 SHA-256。
4. 先部署的 SEO 兼容 release SHA 和兼容回滚 release SHA；两者都接受 0094/0095，
   并保留未知/多 revision/缺字段拒绝。仅测试中 patch 白名单不算完成。
5. 最新有效备份/PITR 恢复点、恢复能力验证、所有共享模块发布/迁移暂停凭证。

凭据通过既有受限运维凭据设施在运行时提供；不放 argv、审批 JSON、artifact 或日志。
不增加 root SSH，不关审计，不依赖未经确认的账户权限。
入口校验身份和所有产物后，在同一连接同一事务中重新核验起点与结构，不能直接相信旧快照。
显式约束 public Schema、版本表位置和表名解析；不得允许用户自选 schema/目标/head。

执行事务流程：固定 search_path（显式考虑 pg_catalog/临时表遮蔽）→ 短时锁定版本表 →
重新验证单行 0094、目标对象缺失及基线 → 通过专用 Alembic env 执行唯一 0095 →
核验表/字段/约束/FK/索引/序列权限、版本单行 0095 → 提交。
不得手工 UPDATE 版本表、stamp、重放前序历史；超时/校验失败必须整笔回滚。
已是 0095 则只报告“已执行，拒绝重复”，不得回退起点重试。

版本表锁只能约束合作的迁移器，不能阻止外部 CREATE/ALTER；所以运维停并发是独立前提，
不能拿锁代替暂停发布。锁/语句/总执行超时必须结合数据库规模和维护窗口获批。
当前本地 1 秒锁/10 秒语句超时不是未经审核即可套用的生产 SLA。

## 3. 故障与回滚

- 提交前失败：事务回滚；只读确认版本和目标对象恢复原状，不自动重试。
- 提交响应丢失/连接断开：结果未知；重新只读确认，不假设失败后直接重跑。
- 提交后应用异常：保持 SemTask 关闭、保留表和工单；使用接受 0095 的兼容应用回滚版。
- 禁止删表/downgrade/改版本行。共享库 PITR 恢复可能丢失三个模块恢复点之后的新数据，
  不能作为无人确认的自动回滚；需要跨模块停写和单独事故授权。
- 验收读取版本、结构和三模块健康，不创建真实客户工单或写百度来“验证”。

## 4. 业务约束不能遗漏

SemTask 对 tenants 的 ON DELETE RESTRICT 会阻止任何存在工单的客户物理删除，
包括已完成/取消工单。GEO 日常内容归档不受影响；彻底注销客户须走统一保留/注销策略，
不在本迁移中级联删除工单，不把“清空任务”当作回滚。
