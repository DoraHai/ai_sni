# GEO 后台执行与开通状态规则

所有 GEO 后台入口在实际执行时读取 `tenant_modules`，只允许当前为
`active`/`trial` 且尚未到期的客户继续。HTTP 入队时已经通过鉴权不代表后台执行时仍可用。
撤权不删除历史任务、历史指标、发布记录或投递日志。

| 后台入口 | 撤权前已开始 | 远程请求正在执行时撤权 | 撤权后才被调度 |
|---|---|---|---|
| 母稿异步生成 | 模型调用前复核 | 返回后丢弃生成结果，作业失败，内容任务恢复编辑态 | 领取后失败，不调用模型 |
| 渠道稿生成 | 每个渠道及模型调用前复核 | 返回后丢弃结果，不新增或更新渠道稿 | 不生成渠道稿 |
| 批量发布 | 每个渠道发送前复核 | 停止后续渠道；本次投递记为 `unknown`、保存去敏结果并标记需人工核验，不创建发布成功记录 | 不发送 |
| 可见度巡检/复测 | 每个问题与引擎组合前复核 | 返回后丢弃回答，不写快照或正式指标 | 不创建或执行巡检 |
| 夜间指标重建 | 计算前复核 | 提交前再次复核，撤权则回滚本轮新指标 | 跳过客户 |
| 已发布页面监测 | 抓取前复核 | 返回后丢弃观察，不写健康状态或新工单 | 不抓取，不写失败退避 |
| 效果复盘 | 读取指标前复核 | 提交前再次复核，不写复盘结果或新工单 | 不评估，不写失败退避 |

批量发布是唯一可能在系统得知撤权前已经对外产生效果的入口。此时保留的
`push_deliveries` 记录属于最低审计证据：状态必须是 `unknown`，可以保存渠道、账号、
尝试次数和去敏后的远端 URL，但不得保存响应正文、令牌或凭据，也不得标为发布成功。
写入该审计记录前先回滚连接器产生的凭证刷新和其它待提交业务变更，再重新加载并锁定
原投递 reservation；如果人工恢复已经改写 reservation，后台不得覆盖人工核对结果。
恢复发送前必须由操作人员在渠道后台核对实际结果。

发布记录、历史监测状态、历史指标和任务证据属于已经发生事实的审计记录，撤权后继续保留。
保留记录不授权新的抓取、生成、发布、指标计算、自动关闭、自动重开或新建客户工单。
