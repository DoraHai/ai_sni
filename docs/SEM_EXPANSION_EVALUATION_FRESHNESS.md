# SEM 拓词评估有效性

- 普通评估仍只处理未评估候选。旧结果不删除，不自动重评、不自动采纳。
- 每次成功评估在现有 `keyword_candidates.raw` 的保留命名空间
  `__sem_ai_evaluation_v1.context_hash` 写入客户 ID、名称、行业、业务描述、品牌词根
  及评估提示词的 SHA-256；不保存新的敏感凭据，不增加表或字段。
- 列表只读比较指纹：匹配为当前资料下评估；不匹配为画像或规则已变更；
  无指纹的历史结果为未核验，不能推定确实发生过画像修改。
- 同步可能替换 `raw`，导致旧评估的指纹丢失，此时保守标为未核验，不伪报有效。
  本次不修改 `app/baidu/**` 同步实现。SQL JSON 局部更新保留评估提交时的其他 raw 字段。
  数组/标量等异常 raw 原样保留，不为写标记而清空；结果继续显示未核验。
- 并发重评时，整组 AI 结论字段与指纹一起写入，避免 ORM 省略“相对本地快照未变”的字段
  而混合两次评估。此处保证一致性，不保证请求开始时间较晚的一次一定胜出；
  最后完成写入的一组结果生效，旧画像对应的结果仍会标过期。
- 旧结论和人工状态、预设价格保留，旧结论仍参与相关性筛选；页面和 CSV 明示有效性。
  过期或未核验的 AI 建议出价不再由候选 API 返回给加词表单作为默认值。
  AI 建议及历史缓存还需通过有限数值、非布尔和 0.01–999.99 元范围校验；
  无效建议不作为表单默认值，人工预设不受影响。
  保存和读取还共同要求 relevance=relevant、recommend=adopt/watch，并且 PC/移动
  至少一项百度指导价在有效出价范围内。generic 或无指导价时不返回 AI 出价；
  模型自行返回的“指导价”字段不算依据，读取侧同样保护历史缓存。
- 模型结果按结构、枚举与字段类型校验：异常整批进入受控失败分支；
  异常条目、重复词结论不覆盖旧值，计入待重试，正常条目与后续批次继续处理。
  非本批请求词直接忽略，不字符串化数组/对象冒充词或结论。
- 运营通过现有“新一轮小批量重评（含旧结果）”手动确认重评，每批最多 20 词，
  包含旧结果，不限定为过期词，不自动继续。失败保留旧值。
- 竞品行业相关性和投放价值分开：允许 relevant/drop；不把竞品强制采纳，
  不把“不值得投放”自动等同“行业无关”。提示词测试不保证真实模型每次正确。

## 发布与验收

功能 PR 合入 main 后分别走 SEM 后端、前端同步 PR。建议先后端后前端；
旧前端可忽略新增字段，但只有新前端会显示警告。首次发布不会回填存量指纹。
生产需单独批准发布和重评；本次只本地开发与离线测试，`migration=not-run`。
不执行 Alembic，不修改生产画像/候选，不部署或重启任何服务，不涉及 Nginx。

离线测试覆盖客户隔离、资料/规则变化、历史元数据缺失、AI 失败保留、
并发资料变更时不冒充新画像结果、SQL 局部写入、分页计数与 CSV 提示，以及 UI 批次边界。
真实模型质量仍需发布后单独批准的小样本人工复核。
