# 单页检测保存图片证据

## 修复范围

单页 `POST /api/v1/seo/site-pages/{page_id}/audit` 原先调用 GEO 诊断，仅更新页面资产，不保存 SEO 图片证据。本次改为 SEO 安全抓取与 HTML 解析：读取 robots.txt 后，只检测指定页面及必要 HTTP 重定向，不读取 Sitemap、不遍历链接、不加载图片、不调用 AI、不发布。

评分与问题代码统一采用 SEO 网站扫描口径（每个规则问题扣 10 分），不再使用 GEO 的问答/AI 爬虫等加权评分。页面当前 TDK 为此次读取的事实；成功检测不覆盖人工 TDK 建议、不修改内容任务。

“补抓待检测页面”也使用同一条检测/持久化路径，保持最多 20 页的候选上限，不再调用旧 GEO 诊断。逐页提交，单页失败不回滚已完成页面；加锁后重新判断是否仍待补抓。批次运行超过 70 秒后不再开始下一页，预留单页 40 秒网络期限和保存时间，未执行页面在响应 deferred 中明确报告，可下次继续。权限和租户检查在候选选择之前执行。

HTML 中畸形链接（非法端口、无效 IPv6 等）按单个属性忽略，不让无关锚链接、Canonical 或 hreflang 阻断整个页面/图片证据保存；安全 URL 校验与逐跳 IP 固定保持不变。

## 持久化与隔离

- 复用已存在的 SeoCrawlRun/SeoPageSnapshot，无新增数据库迁移。
- 单页 run 使用 max_urls=1、single_completed/single_failed；快照 discovery_source=single_page。
- run、快照和页面状态同一事务提交。失败快照不带图片明细，读取接口不会回退到旧成功证据。
- 快照记录观测结束时的显式 CST，匹配现有快照字段时区约定；页面 checked_at 仍为 UTC。
- 入口校验 SEO 订阅、编辑权限、租户、页面和所属网站。前端同时传 site_id；旧客户端缺省 site_id 时仍按存储记录验证所属网站。
- PostgreSQL NOWAIT 行锁拦截同页并发操作；网络总截止 40 秒。
- robots 禁止或暂不可核实时不访问页面。失败不评分、不冒充健康；已批准建议保留，未确认建议按生产既有失败策略撤销。
- 成功读取的空 robots.txt（以及仅空白/注释）按无限制规则处理；空正文但有超时、非文本或 HTTP 错误仍不能放行。
- 单页目标和实际 HTTP 重定向保留尾斜杠、重复斜杠、路径参数及查询字符串；仅移除 fragment。去重键的旧规范化方式不再用于改写实际 HTTP 请求。
- 全站扫描列表和概览排除 max_urls=1。指定一个不属于全站列表的 run_id 也不会返回单页快照冒充全站扫描。

## 本地验证

运行全部 tests/test_seo*.py；图片证据与诊断 Vue 测试；SEO 构建与产物隔离检查。
新增 SQLite 隔离数据库测试真实提交后换 Session 读取，验证 JSON 明细、事务回滚、后续失败不回退旧证据。SQLite 不代替 PostgreSQL 的行锁测试；NOWAIT SQL 与锁冲突错误处理由单元测试覆盖。

本轮不连接生产数据库、不抓取诺德、不调用 AI、不部署。

## 生产同步复核点

开发基线是 main f64e342，不能把 main 整棵树覆盖生产 SEO。后续应通过独立 SEO promotion PR 仅同步此修复。
生产分支额外有批量检测调用和页面前后对比 UI：同步时将批量单页调用也传入 site_id，并将“至少两次全站扫描”改为“同一页面至少两次有效检测”的准确文案；保留失效链接来源依赖全站扫描的提示。
保留生产抓取器现有 SSRF/IP 钉住、internal_link_details、失败判定等加固。新单页存储会去掉辅助链接数据，不生成监控关系。

发布后才执行已授权的 #234 单页验收：只点一次检测；核对明细总数、缺属性/空白分类、URL/区域和刷新持久化。失败时停止，不扩大到全站扫描。
