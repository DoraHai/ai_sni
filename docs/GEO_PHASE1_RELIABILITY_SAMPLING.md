# GEO 第一批改进：任务执行与采样来源

基线：`e0d2ff2`，分支：`codex/geo-reliability-sampling-v2`。

## 已实现

- 每个异步作业使用独立命名的 PostgreSQL 会话咨询锁；执行使用持锁连接，业务提交不释放锁。重复调度未取得锁就退出，领取还受 pending 条件更新保护。
- 启动恢复及超时查询跳过活跃持锁作业。无持锁者的中断 running 作业标失败，避免自动重放可能已产生外部效果的发布；pending 可重新排队。
- 回答生成不再注入待测品牌，原始问题保持不变。单独请求判读回答；失败保留原文、返回 needs_review，引用准确性默认 unknown。
- 新采样返回 `unprimed_json_v2` 方法标识，巡检记录和保存备注保留标识。人工确认探测结果时保留 API/模拟来源，旧调用默认为 manual。
- 修复品牌测试替身和当前客户工具栏契约，增加任务所有权、采样隔离、判读失败和来源保存测试；接入 GEO 门禁。

## 限制与下一步

- 所有权测试覆盖应用并发分支及锁释放协议，尚未完成真实 PostgreSQL 双连接/多进程集成验证。发布前需在一次性数据库上验证跨提交锁保持、进程终止释放、并发领取和恢复跳过活跃作业。
- 会话锁要求直连 PostgreSQL 或保持会话语义的连接；不适用于事务级连接代理。升级时应避免新旧 worker 混跑，旧版本不遵守此锁协议。
- 任务执行期间持续占用一条数据库连接；应在测试环境观察并发和连接池容量。长时间失去响应但连接仍活跃的任务不会被查询接口强制释放，后续需要执行超时/取消机制的专项验证。
- 两阶段采样增加一次模型调用及相应延迟、费用；这是API JSON回答采样，不宣称等同消费者网页/App回答。
- 现阶段只保留方法标识，历史趋势尚未按方法版本自动分组隔离；模拟样本核心KPI默认排除策略、完整证据详情页和浏览器主流程验收仍是后续切片。
- 未修改 `app/models`、迁移、共享认证、SEM或SEO；GEO专属页面位于 `frontend/src/views/geo`，仅为保存采样来源而修改。
- 无数据库结构变更，无生产迁移、远程推送或部署。所有业务改动保留为本地未提交差异。
