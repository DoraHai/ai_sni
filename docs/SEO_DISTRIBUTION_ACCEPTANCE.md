## 统计与契约

新指标 `seo.backlinks.verified_count`：当前网站 active 且最近一次抓取 state=found 的来源页面/目标页面唯一外链数量。索引候选不计入。沿用原 trend_7d 结构，历史不足返回 null。只有 seo.links 查看权限者在快照中获得此项；原五项权限要求保持不变。

任务新增 action_type=backlink_outreach，params 包含来源 URL/主机名、可选机会请求 ID 和最多 100 条跟进。完成证据指向该来源主机、任务创建后首次发现并抓取确认的新链接，同时要求真实指标增长。共享任务字段和状态不变。

分发效果展示最近 200 条有地址的发布记录。访问及转化录入按来源 URL 保存最近一期报表（最多 500 个来源），标记 user_reported，独立于抓取证据。

### 我会提前做的准备

核对线上版本和当前站点、确认 SEO 内容编辑权限及审核稿证据有效，准备本地环境、最新填稿包与记录表。缺少正文或事实证据时先整理草稿，待你确认可对外发布后走现有审核。助手启动的独立浏览器需要现场登录，普通浏览器已有登录不代表助手已登录。

### 现场顺序与通过标准

1. 核对平台账号、站点、问题网址和稿件版本后开始。问答每个平台至少走通一篇；文章每个平台至少走通一篇，图片与正文分别确认。
2. 先选中空白回答编辑区填稿：文字完整，未误填标题、搜索或评论框，无自动点击发布。已有内容不得覆盖；不合适的编辑器应停止并给出提示。
3. 人工检查正文、事实出处、链接、排版、图片与平台要求，再由你点击最终发布。平台需要审核时记“审核中”，不得记为公开发布成功，也不为了测试故意提交违规内容。
4. 公开后复制真实网址。问答在终端生成回执，在工作台“分发与效果 → 回填网址”导入，检查后保存；状态应为待核验。文章按现有链接回收流程操作。
5. 抓取核验正文和官网链接。可读且正文吻合才能记录匹配；要求登录、验证码或抓取失败应显示“无法核验”，不能伪装成功。人工能看到内容但服务器不可读时，分别记录人工观察与系统结果。
6. 中断恢复：关闭本地浏览器后，用 `python qa_runner.py task.json --receipt-only --answer-url "公开回答网址"` 补生成回执，应不打开浏览器、不重复填稿。旧版脚本不支持该命令时先取得最新版脚本，保留原 task.json。
7. 外链按预览 → 导入 → 去重 → 核验 → 分析顺序检查。导入候选不自动算有效外链；失效、无链接及抓取失败区分展示；真实样本缺失的新增/丢失场景留待补测，不编造历史结果。
8. 我记录并修复失败点，回归后只复测受影响环节及必要关联流程，再提交部署。只有实际通过的平台列入真人验收已通过名单。
