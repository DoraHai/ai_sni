# 超管系统配置交付与启用审核

本次增加“系统配置”页，覆盖 21 组模块接口配置：SEM 百炼、DeepSeek、百度开发者；SEO 百炼、DeepSeek、站长之家、DataForSEO、远程 PageSpeed；GEO 百炼、DeepSeek、站长之家、远程 PageSpeed、八个采样服务商和腾讯 WSA。

站长之家每个模块提供通用及七个专用密钥槽，支持首次配置；按不同接口分别维护按次价格。DataForSEO 登录账号及密码一起加密保存。模型、官方 HTTPS 地址、支持的超时与平台默认启用状态为公开参数；八个 GEO 引擎使用平台默认配置，延续当前生产的凭据优先级。

## 数据与生效边界

- 固定配置目录；不接受数据库、JWT、加密主密钥、资金写回开关等任意字段。
- AES-GCM 加密密钥包，接口只返回存在状态；页面、审计不包含密钥、登录账号、密文或请求正文。空输入保留原值，明确清除或恢复原服务器配置需由超管选择。
- 固定官方域名限制，不允许认证 URL、查询参数、内网/IP、非 HTTPS 或任意代理地址。
- 命名全局管理员和客户/账号双编辑权限；保存前重新鉴权，UUID 幂等、版本冲突保护、事务内审计。
- 模块配置分别读取。新请求或后台任务使用新配置，已经运行的一轮保持其配置快照；缓存的服务器默认 Settings 不被修改。
- 业务运行配置以服务器登记值展示，包括排名采集、GEO 调度/执行/巡检/生成/发布/恢复与限额。此类调度参数仍通过发布配置管理，本页不伪装为可即时修改。
- 客户专属授权、SEO/GEO 发布账号、监测引擎与服务计划在原客户范围管理，提供已有入口。
- PageSpeed 当前默认使用本地 Lighthouse，此项仅管理远程适配器配置，不切换默认检测路径。

## 调用与费用

本月服务商统计按模块、服务商、模型及实际接口分组，站长之家不受最近 50 条明细限制。费用仍来自原调用台账，按客户/账号与系统任务分别汇总。已配置单价仅作用于后续调用；不补算缺失旧账，不把未定价金额显示为零。保存配置不发起付费连通测试，配置存在与接口健康分别展示。供应商实际账单对账、退款仍属于后续独立工作，当前不声明已实现。

## 调用明细与运维补齐

- 超管 `GET /api/v1/admin/console/usage` 支持北京时间日期、客户、账号、模块、服务商、具体接口、模型、状态与是否定价筛选。客户/账号值 0 表示未归属客户或后台无登录账号。每页最多 200 条，按时间与 UUID 稳定翻页，后续新增请求不插入已开始的分页。缺失费用保留为空，明细与汇总为同一台账。
- `GET /api/v1/admin/console/usage/export` 以相同筛选导出完整 CSV，最多 50000 条；超出明确拒绝，要求缩小范围，不截断。导出保护公式单元格，不输出密钥引用、单价原文、请求/响应正文。两个接口只读事务、限时、全局实名管理员鉴权，不依赖管理迁移即可使用。
- 告警提供稳定来源编号、认领、处理说明、标记已处理与重新打开，复用 `api_control_audit`，无新增迁移。版本检查与请求幂等防止多人覆盖；同一来源有新异常时重新提醒。标记处理不修改任务、授权或上游状态。外部消息发送渠道尚未接入。
- 服务商健康来自 24 小时真实台账；异常至少 3 次且占比达到 20% 时提醒。不额外探测供应商。已接入域名可人工登记 CNY/USD 余额、套餐次数、到期日和提醒阈值；未知值与零区分，显示人工来源及时间，不冒充自动同步，不合并不同币种。
- 账号创建、启停、客户范围、角色权限修改、角色删除及密码重置新增审计。业务变更与审计同一事务；启用后审计失败则整体回滚。只记录密码已变更标记，不记录密码或哈希。API Key 操作者使用保留编号 0，命名账号使用实际账号 ID。管理未启用期间保持原行为，并在页面明确审计待启用，不追补历史。
- 生产运维脚本 `scripts/platform_database_backup.py` 显式执行私有公共业务库归档；仅向 `/opt/sem-backend/platform-backup-status.json` 写入无密钥、路径和业务数据的元信息。页面分别显示备份结果、归档校验与恢复验证。归档可读不等于恢复已验证；脚本不会迁移、恢复或删除旧备份。超过 36 小时、失败或结果未接入会提醒。定时备份和完整恢复演练仍需单独建设。
- 告警处理、人工额度与账号角色审计代码先随 SEM 后端上线。它们依赖此前同一份待审核管理 SQL；未审核前不执行生产 DDL、不启用管理开关。调度启停与任务重试保留模块原工作区，待 SEO/GEO 自动化流程完善时整合。

## 生产数据库审核对象与启用顺序

1. 人工审核 `scripts/api_controls_schema.sql` 与 `scripts/api_controls_permissions.sql`：四张新管理表，在现有调用台账新增一项可空预算预留字段；此次 SQL 包括固定连接配置类型与公开登记 metadata。不更改客户/账号数据、不更改 Alembic 版本、不删除旧台账。
2. 代码通过各模块现有 Git 发布流程上线，管理开关保持关闭。结构脚本在生产尚未执行；不能把旧的费用台账建表授权当成本次迁移授权。
3. 确认生产不存在四张管理表及新增字段；执行前备份现有数据库与三个服务环境配置。核对三个服务使用一致的 HMAC 盐及 AES 主密钥，只报告一致性，不输出原文。
4. 经人工明确审核批准后，以现有对象所有者执行结构和权限脚本。SQL 使用事务、3 秒锁等待、15 秒执行超时；非幂等脚本不要重复执行。运行角色无 DELETE，审计仅 SELECT/INSERT。
5. 保持现有 API 计量开启，在三个服务逐个启用 API_CONTROLS_ENABLED 并通过既有运行管理方式重启；核对健康、配置登记、全局管理员权限以及匿名/客户拒绝访问。不设置默认预算、禁用接口或替换生产密钥。
6. 核对全部 21 组登记及模块运行参数，确认已配置的密钥槽只显示存在状态。没有合同单价的接口等待超管填写，不能编造价格。

回退：关闭管理开关并通过原发布流程回退应用。保留新表和既有费用台账；不执行删表或修改客户权限。
