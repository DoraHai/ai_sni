- 网站体检与评分；

## 四、当前已经完成的功能

### 1. 独立诊断中心

- 诊断中心已经从旧的 `/deal-sniper/portal` 诊断页面拆为独立模块；
- 正式入口固定为 `/diagnostic-center/`；
- 侧边栏四个诊断页签直接跳到对应报告区；
- 基础信息、目标用户和知识库保持在同一个诊断中心壳内；
- 平台门户和模块入口已修正到正式诊断中心地址。

### 2. 单页与全站诊断

- 支持“单页快速诊断”和“全站抽样诊断”；
- 全站优先读取 Sitemap，失败时从首页站内链接发现页面；
- 最多抽样 10 页，并发数 3；
- 权重：输入首页 3、产品/服务等核心页 2、普通页 1；
- 对重定向后的最终 URL 去重；
- 输入地区首页时不再额外抓取可能跳往其他地区的域名根首页；
- 每条规则保留逐页证据；
- 当前规则版本 `v1.1.0`。

计分说明见：

- `docs/diagnosis-scoring-methodology.md`

### 3. 扣分原因

- 所有有扣分的规则卡片都会显示“扣分原因”；
- 全站报告展开后，每个未通过页面都会显示：未满足的规则、页面当前证据和失败原因；
- 原来的 `-1.3` 等扣分数字保持不变；
- 老报告由前端兼容生成原因，新报告会在后端结果中直接包含 `reason`。

示例：

```text
未通过 · 整体硬质合金钻头
原因：未满足“Meta 描述可摘要”规则：当前长度：8
```

### 4. 品牌建档引导与数据隔离

首次体检流程已改为：

1. 填写官网；
2. 从官网自动识别；
3. 用户确认品牌信息；
4. 保存后自动开始网站体检。

首次必填四项：

- 官方网站；
- 品牌名称；
- 所属行业；
- 至少一项核心产品或服务。

自动识别来源：Schema.org、`og:site_name`、页面标题、Meta Description、H1/H2；DeepSeek 可用时只负责把官网事实整理成结构化候选值，保存前必须由用户确认。

品牌资料不会再读写 `tenants.name`、`tenants.industry` 等 SEM 客户主数据，而是存入 `tenant_memories`：

- `mem_type = diagnosis_brand`
- 内容按网站域名保存多个 profile；
- 域名键会去掉 `www.`；
- 当前活跃档案由 `active_key` 标记。

生产验证过 Kennametal 官网，能够识别：

- 品牌：Kennametal；
- 行业：金属加工；
- 核心产品候选：孔加工、车削、硬质合金立铣刀等。

未完成当前域名品牌档案时，创建诊断接口返回 HTTP 409，避免网站与品牌资料错配。

历史 SEM 租户 `tenant_id=1` 仍为“苏尔寿”，没有被诊断中心修改。

### 5. DeepSeek 真实抽样

- 已接入真实 DeepSeek API 做品牌提及抽样；

- 品牌命中由后端按确认后的品牌名称和品牌词根确定；

## 六、主要 API

- `POST /api/v1/geo/audits`：执行单页或全站诊断；
- `GET /api/v1/geo/audits/latest`：最近一次诊断；
- `GET /api/v1/geo/audits/{id}`：诊断详情；
- `POST /api/v1/geo/audits/{id}/advice`：生成行动建议；
- `POST /api/v1/geo/audits/{id}/ai-sample`：DeepSeek 品牌提及抽样；
- `POST /api/v1/geo/assets/brand/discover`：读取官网并生成品牌候选信息，不落库；
- `GET /api/v1/geo/assets/profile`：按网站读取品牌档案；
- `PUT /api/v1/geo/assets/brand`：保存按域名隔离的品牌档案；
- `PUT /api/v1/geo/assets/audience`：保存目标用户；
- `GET/POST/DELETE /api/v1/geo/assets/knowledge`：知识库管理。

## 十一、已知限制与后续建议

这些不是当前故障，但新窗口继续扩展时需要知道：

1. 品牌基础信息已经按域名隔离，但“目标用户”和“知识库”目前仍主要按租户保存；如果同一账号管理多个诊断网站，建议下一步也按网站域名隔离。
2. 最近诊断记录目前按租户取最新一条，而不是按域名列出多个项目；多网站场景建议增加“诊断项目/网站切换器”和按域名的历史记录。
3. 全站诊断是同步抽样，最多 10 页；更大规模抓取应改成异步任务、进度查询和可恢复队列。
4. 旧报告没有后端持久化的 `reason` 字段，当前由前端兼容展示；重新诊断后会得到完整持久化原因。
5. 历史报告生成建议时保留了旧租户资料回退逻辑；新诊断已被品牌建档前置校验保护。后续若完全迁移完成，可以再移除该兼容回退。
