## 来源及边界

根据 2026-09-03 对老虎客户已填写业务说明的只读核对，抽象出粉末涂料场景：企业采购、
材料选型与技术咨询为重点，艾仕得和阿克苏诺贝尔是同行竞品。样本使用虚拟客户名，
不保存真实租户 ID、百度 UCID、密钥、原始客户记录或账户统计。

服务地域及非经营范围未确认。交通运输应用不等于经营汽车修补漆，建筑建材应用不等于经营
家装乳胶漆；不得把待确认范围写成确定排除项。工业数码打印油墨也尚未确认，不纳入本轮核心词。

此前线上重评的 20 词以竞品名称变体为主，结果为 19 个 watch、1 个 drop，全部 relevant。
这证明不了模型能区分噪音和无关词。下列 20 词是另外构造的离线验收样本；旧提示词下的一次
真实 qwen-plus 结果见下方记录，不代表生产使用该模型。

## 样本设计

数据文件：`tests/fixtures/sem_expansion_acceptance_v1.json`。

| 分组 | 数量 | 验收预期草案 |
| --- | ---: | --- |
| 采购 / 产品选型 | 4 | relevant；允许 adopt 或 watch，均不代表执行许可 |
| 竞品 / 比较 / 替代 | 4 | relevant；按各词允许 watch 或 drop，不直接 adopt |
| 官网导航 / 信息查询 | 3 | relevant 与投放价值分开；官网 drop，其余 watch 或 drop |
| 通用噪音 | 3 | generic；watch 或 drop，不能输出 AI 出价 |
| 明确无关 | 3 | irrelevant/drop，不能输出 AI 出价 |
| 产品边界 | 3 | allowed_pairs=null，等待业务确认，不纳入分类正确率分母 |

17 个词有草案预期，3 个边界词单列。全部 relevant 的退化策略至少不满足 6 个明确负例。
这些标签是工程验收建议，并非负责人已确认的金标准；业务审核可调整，但应保留调整原因和版本。
模型价格、搜索量、竞争度不能凭空填入样本。测试中的 4 元指导价和 3 元建议价均是合成输入。

## 离线测试实际验证什么

运行：

```text
python -m pytest -q tests/test_sem_expansion_acceptance.py
```

- 20 个唯一词、6 个分组、17/3 评分分界、标签枚举及资料边界完整。
- 生产提示词构造函数只接收画像和候选词，不接收预期标签及解释，避免答案泄漏。
- 使用模拟模型返回值，运行真实 `_evaluate_batch` 解析器；噪音、无关、drop 或缺指导价时隐藏
  AI 出价及理由，相关/watch 不会被强制改为 adopt。
- 测试拒绝 socket 网络连接，并默认拦截模型入口；不创建数据库会话，不执行候选写入流程。
- 模拟返回与网络拦截共用同一清理作用域，每项测试结束后核对入口已恢复，避免污染后续测试。

**测试通过只证明样本及解析保护契约通过，不代表真实 DeepSeek 的 17 个词判对，也不代表
17/17 准确率。** 模拟相关性输出不能验证模型的真实相关性判断。新提示词的真实模型验收未执行。

## 2026-09-03 历史观测与 PR #244 修订

在另行获得一次性调用授权后，用相同虚拟画像与 20 词请求 qwen-plus，仅 1 次、无重试。
输入未包含预期标签、指导价、搜索量或竞争度。按尚未最终批准的草案为 13/17；
3 个范围待确认词不计分类分数。不能将该比例推广为模型准确率或据此更换生产模型。

历史返回转录于 `tests/fixtures/sem_expansion_qwen_observed_20260903.json`，与预期标签文件分开。
保存模型名、时间、旧提示词哈希及 20 项原始结果字段，不保存认证信息；它不是新提示词结果。
后续修改预期标签或画像时，应另建版本，不能覆盖此次输入及历史偏差来提高分数。

PR #244 仅修改 SEM `app/ai/expansion_eval.py` 的提示词，没有修改解析器、API 或资金回写逻辑：

- 按业务依据 → 语义相关性 → 投放建议 → 出价依据依次判断，防止无采购意图被当作行业无关。
- 已知同行的公司信息、官网、技术资料仍区分 relevant 与 watch/drop；未知投放策略不能抹去已知同行关系。
- 未确认策略的竞品替代选型保持 watch，不因出现“替代”自动推荐 adopt。
- 未提及相邻产品不等于排除其经营范围；提示资料待确认，明确跨行业无关词仍可排除。
- 缺指导价时两项报价字段均为 null；不编造搜索量、竞争度或转化表现，JSON 示例也使用 null。

离线回放验证 4 个虚构报价在解析层和 API 输出层均被既有保护清空，不影响人工预设。
当时合法格式的语义错误仍会通过解析器。PR #244 的测试记录了这一局限，没有硬编码品牌修正，
也没有把提示词文本断言当作模型质量测试。

提示词属于现有画像指纹的一部分；若后续发布，旧结果将标记为 stale，AI 报价不再展示。
不会自动删除、覆盖、回填或重评历史结果；人工显式重评仍遵守每批上限和确认流程。

## 第二次观测与 PR #245 结构化依据校验（历史版本）

对 PR #244 合并版本 c26b663 的一次授权 qwen-plus 复测为 14/17（仍是草案预期），
虚构报价从 4 条降到 0 条，竞品替代词变为 watch；3 条同行信息词仍 irrelevant/drop，
3 条范围待确认词仍直接排除。中文理由在终端输出时乱码，未伪造或重构原文，也没有为补记录重试。
故未同步生产。本轮不把两次单次观测当成稳定效果结论。

PR #245 仅在 SEM 评估器增加 `basis` 返回契约和校验，保留既有 API/数据库字段与写回流程：

| 模型依据 | 代码检查与处理 |
| --- | --- |
| in_scope / peer / out_of_scope | 必须引用当前客户 industry 或 business_desc 的连续原文（2–500 字符），不接受名字、AI 总结或候选词作为画像依据 |
| peer 与 irrelevant 冲突、peer/adopt、信息意图却 adopt | 不按品牌纠正为“正确答案”，降为 generic/watch，清空报价，说明待人工确认 |
| unknown、依据缺失/非法、引用编造 | 一律 generic/watch；不保留模型原来的武断解释 |
| 已知同行导航 | 仅一致的 relevant/drop 可通过；不自动执行忽略或加词 |
| 结构自洽的普通相关、无关、噪音 | 保留其不同标签，继续走原有价格保护；不是全量改为 relevant 或全量默认采纳 |

所有 peer/adopt 暂不放行，即使自由文本提到竞品投放策略；本契约没有结构化投放许可。
业务“待确认”复用现有 generic/watch 和明确理由，无 Schema 变更；generic 原有展示标签仍可能
偏向“通用”，需结合理由阅读。校验依据本轮不新增数据库存储，也不作为任何真实写回的授权来源。

**真实原文引用不等于语义证明。** 模型仍可能引用真实主营描述，却错误自报 out_of_scope，
这一种自洽但错误的组合仍可能通过。测试显式保留这个反例，不声称已解决所有语义误判。
同样，模型没有返回新 basis 时全部进入待确认，不表示准确率提升。后续实测必须分别统计原始标签、
依据错误、降级比例、正负例区分能力；不能只给应用改写后的标签打分来掩盖模型质量问题。

提示词已包含新契约，因此现有指纹会失效；无指纹历史结果仍为 unverified。若后续批准发布，
旧缓存不会自动改写，新调用的待确认结果按现有成功计数缓存，但不算业务验收通过；再次评估需人工 force，
不会自动增加模型请求。仍须单独质量验收和发布授权。

## 中文无损记录工具（纯离线）

`scripts/sem_expansion_eval_record.py` 不读取密钥，不导入应用配置，不含网络或数据库调用。
后续获准调用模型时，应在收到 message.content 后、任何终端打印之前调用 `save_record`。
传入恰好六个字符串字段：source_commit（40 位 SHA）、model、system_sha256、user_sha256、
observed_at、model_output（原始 message.content，包含 basis；即便为空或不是合法 JSON 也原样保存）。
不要传请求 headers、客户端配置、Token 或完整 HTTP 交换内容。字段白名单不是敏感内容脱敏器。

文件以 UTF-8 保存，中文使用 JSON Unicode 转义，解码后逐字还原；不依赖 PowerShell 编码。
输出必须在工作区仓库之外，目标必须为新文件，不覆盖历史记录、不自动创建目录。
CLI 仅转换已有 UTF-8 输入文件：

```text
python scripts/sem_expansion_eval_record.py --input <六字段记录.json> --output <仓库外的新记录.json>
```

终端只输出英文成功/失败摘要，原文只存在记录文件；旧乱码无法靠此工具补回。离线测试验证
ASCII 控制台、中文、emoji、换行、非法模型 JSON 原文保留，以及拒绝覆盖和意外认证字段。
现有数据库冒烟脚本仅更新其模拟返回契约，本轮未执行它或连接任何数据库。
