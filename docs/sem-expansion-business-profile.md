# SEM 拓词评估：客户业务资料

本次只修改 SEM 拓词 AI 评估，不修改共享客户模型、SEO/GEO、百度写回或发布配置。

- 使用现有 `tenants.industry`、`tenants.business_desc`、`name`、`brand_terms`。
- 在「客户画像」填写行业/业务描述；业务描述可包含产品、目标买家、服务地域和非经营业务。
- 行业与业务描述至少填写一项；都为空时评估接口返回 409 和补充资料提示，不调用模型、不更新候选。
- 不根据客户名称或候选词推断缺失行业，不将 AI 画像总结作为已确认业务事实。
- 资料仅用于建议；不自动加词、否词、改价或改变真实回写权限。

## 已有评估结果

保留现有缓存语义：默认只评估尚未评估的 pending 候选。
本次不会清空或回填已有客户数据，也不会自动重评历史结果。
未来经审核发布后，或运营修改客户业务资料后，使用「小批量重评（含旧结果）」
（`force=true`，每次最多 20 个去重词）更新 pending 候选的旧建议；已采纳/忽略的候选不在重评范围。
重评会调用模型并更新本地建议，但不会执行百度写回；模型失败的批次保留旧结果。
因此不能仅凭发布成功就宣称历史建议已经按新资料更新。

## 小批量验收

- 默认「小批量（仅规划师）」：填写一个种子词，上限 1–20（默认 20）。
- 新接口 `POST /api/v1/expansion/sample` 仅调用该种子词的规划师查询，不调用账户主动推荐、
  搜索词报告或 AI。服务端对去重后的写入再次截断，已有候选可能只刷新指标，不保证新增 20 条。
- 客户必须恰有一个有效百度账户；零账户或多账户返回 409，不猜选账户。
- 返回 `candidates_written` 是本次更新条数，百度未返回多少候选未知，不冒充剩余数量。
- 拉取后单独点小批量 AI 评估。`POST /api/v1/expansion/evaluate` 默认/最大为 20，
  超限返回 422；仅评 pending，默认跳过已评估词，不按页面筛选或勾选限定范围。
- 按每个词当前符合条件记录的最小 ID 排序，成功的同词多源记录共用一次研判。
  `successful_words` 为成功去重词数；`evaluated` 为行数；`failed_words` 含模型漏词；
  `remaining` 为本次游标范围内未成功的词数，包含未进入本批的 `deferred`，不含游标之前失败的词。
- 返回 `next_after_id`（末尾为 null）；点击「继续下一批」传 `after_id`，无论首批是否成功均向后推进。
  `force` 在同一轮保持不变；不会把已经成功更新的前批词重新放回本轮队首。
- 返回 `failed_candidate_ids`，前端累计待重试代表记录 ID。点击「重试失败词」仅将至多本批上限个 ID
  放入 JSON `{"retry_ids":[...]}`，不带非零游标。后端仍按当前租户、pending、force 条件匹配，
  外租户、已采纳/已忽略或已不需评估的 ID 不执行；失败仍保留旧结果。
- 重试不改变主游标，未成功的重试词放到待重试队尾；到达末尾不自动从头开始。
  本轮进度只在当前页面内存保留，刷新/切换客户重置；新一轮会重新查询候选，不是持久化快照。
  同时有其他人增删候选时数量可能改变，新插入的同词来源可能留待下一轮。
- 关闭小批量开关后，原有多源拉取仍在，并需额外确认；该模式保留原自动评估，
  **不受 20 词总量限制，不用于小批量验收**。URL 爬取仍为独立原有路径。
- 不自动采纳、加词、否词、改价；本次未更改真实回写门禁。

前后端须分别经过审核、生产同步 PR 和各自流程发布；新前端依赖新增 sample 接口，
应先发布后端，再发布前端，间隔期间不使用旧前端「全部重评」按钮进行验收。
本次开发不执行发布。旧接口未携带 limit 的调用现默认最多评估 20 词，调用方需读取 remaining。

## 验证与发布边界

回归测试以 mock 模型和内存对象验证不同客户上下文、缺资料门禁、接口提示、
候选租户/状态过滤、force 缓存契约、同词去重和失败保留旧值。
测试不证明模型实际建议的准确率；真实效果需后续经授权在客户资料核对后验收。

`migration=not-run`。不新增/修改迁移，不连接生产数据库，不部署或重启服务。
后续按功能 PR → main → 独立后端同步 PR → 经批准的手动后端发布流程处理。
