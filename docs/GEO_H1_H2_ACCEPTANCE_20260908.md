## H2 剩余真人操作：版本失效

使用具备 `geo.content:edit` 的获授权内容编辑账号，严格按以下顺序操作：

1. 退出 `nord_geo_review`，登录编辑账号。记录用户名、页面角色、当前客户“诺德”和
   `geo.content` 权限；任一项不符立即停止。
2. 打开任务 `#14`。从 `GET /api/v1/geo/content-tasks/14` 的响应和页面记录：
   `review_status=approved`、当前 V5/文章 `#22`、任务 `updated_at`，以及官网、微信、知乎三个
   渠道稿的 ID、`article_version_id`、`status` 和 `stale`。三个渠道稿必须仍未发布。
3. 此时不要生成渠道稿、刷新检查、重新审核或点击发布。
4. 对 V5 做一次确实改变正文、但不增加事实的最小编辑，例如只改一处过渡语或小节标题。
   不改任何事实、数值、品牌、任务标题、Brief 或 CTA。通过页面保存一次，并等待请求完成。
5. 记录 `PUT /api/v1/geo/content-tasks/14/article`：HTTP 状态、请求中的
   `expected_article_id=22`，以及响应中的 `article_changed`、最新 `article.id`、
   `version_no` 和 `review_status`。不得记录请求头、Cookie 或 Token。
6. 保存必须得到 HTTP 200、`article_changed=true`、一个不同于 `22` 的新文章 ID和下一版本号，
   且 `review_status=none`。若返回 409、没有新版本或审核未清空，立即停止并回传。
7. 再次只读 `GET /api/v1/geo/content-tasks/14`，确认审核人和审核时间已清空；原三个渠道稿 ID
   保留、仍绑定文章 `#22`、`stale=true`，页面显示“落后母稿”。
8. 只读 `GET /api/v1/geo/content-tasks/14/push-targets`，记录三个渠道的 `ready` 和完整
   `block_reasons`；页面发布按钮应不可用。不要为了取得报错而调用发布接口。后端发布门禁的
   预期错误为“渠道稿不是最新母稿版本，请重新生成并审校”。
9. 确认历史 V1–V5 仍可查看，旧审核记录仍可追溯。
10. 官网、微信、知乎使用一次批量操作重新生成；对应接口为
    `POST /api/v1/geo/content-tasks/14/variants`，`channels` 包含三个渠道。记录初始 HTTP 状态、
    异步任务 ID、最终状态和失败原因；只点击一次并等待终态。
11. 再次只读任务，确认三个当前渠道稿均绑定最新文章 ID、`stale=false`、状态为 `draft`。
    实现会更新尚未发布的既有渠道稿，因此渠道稿 ID 可以保持不变；不能把“必须产生新渠道稿 ID”
    作为通过条件。
12. 确认 `review_status` 仍为 `none`，到此停止。不重新提交或批准，不配置发布账号，不发布，
    不进入 H3/H4。

以下任一情况立即停止，不重复点击：身份或客户不符；起始状态不是 V5/文章 `#22` 且已批准；
存在已发布渠道稿；保存 409、无新版本或审核未清空；重新生成前任一旧渠道稿未标记
`stale=true`；异步生成失败或只完成部分渠道；审核仍为空时任一渠道变为可发布。

## H2 通过标准

- `nord_geo_review` 能作为诺德普通客户完成一次审核，无需第二名审核人员（已通过）。
- 未审核版本不能发布。
- 保存新母稿后旧批准立即失效，旧渠道稿不能授权或发布新版本。
- 重新生成的三个渠道稿都关联最新母稿。
- V1 至 V5 及本次新版本、历史审核信息均保留。
