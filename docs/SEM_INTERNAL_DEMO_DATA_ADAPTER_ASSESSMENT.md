# SEM 站内演示数据适配评估

## 1. 结论

现有站点、登录流程和 `/workspace/cockpit` 可以继续使用，不需要新增客户可见 URL。用户选择“G-Snipers 全域演示”后，浏览器仍按现有协议提交租户标识；服务端完成身份、租户、模块和菜单权限校验后，再根据主库中的可信演示绑定决定 SEM 读取使用正式数据源还是隔离演示数据源。

前端传入的 `tenant_id` 只能参与既有租户范围校验和服务端绑定查找，不能直接指定 `demo` 模式、连接地址、数据源名称或夹具版本。演示数据源不可用、绑定无效或来源无法识别时必须失败关闭，不得回退到正式数据源。

本轮只给出代码边界、测试要求和实施阻塞项，不修改运行代码，不连接数据库，不执行迁移、装载、同步、部署或真实写操作。

## 2. 当前代码边界

### 2.1 鉴权与租户范围

- `app/security/auth.py` 的 `require_auth` 从 JWT 或 API Key 建立 `AuthContext`。JWT 只保存用户标识，每次请求仍从当前主数据库读取用户和角色；身份判断不是由前端声明。
- `AuthContext.ensure_tenant` 负责校验绑定租户。绑定到具体租户的普通用户不能读取其他租户；未绑定租户的管理员仍须经过现有权限、模块和 SEM 身份校验。
- `require_scoped_auth` 从路径、查询或请求体解析租户，检查多处租户标识是否一致，再校验菜单权限、`tenant_modules(sem)` 和 SEM 身份。
- API Key 不能成为选择演示数据源的旁路。租户绑定 Key 仍只允许其绑定租户；管理员 Key 即使可访问多个租户，也只能读取服务端为目标租户配置的数据源。

### 2.2 数据库会话

- `app/database.py` 当前只有由 `settings.database_url` 创建的全局 engine/session。
- SEM 路由普遍通过同一个 `Depends(get_session)` 会话完成鉴权和业务查询。
- 若直接按请求参数替换 `get_session`，会把身份查询也切到演示库，并使请求输入参与连接选择。这会破坏当前安全边界，也容易产生跨租户读取。

因此，主库应继续承担身份和控制面数据，演示库只承担通过鉴权后的 SEM 业务只读查询。

## 3. 服务端可信演示绑定

建议在主库增加明确的控制面实体，例如 `demo_tenant_bindings`：

| 字段 | 用途 |
| --- | --- |
| `tenant_id` | 关联现有租户，作为鉴权后的查找键 |
| `module_code` | 固定为 `sem`，为后续模块隔离保留边界 |
| `data_mode` | 受约束的 `live` / `demo` 枚举 |
| `source_key` | 引用服务端预配置的数据源注册项，不保存连接串 |
| `fixture_key` | 服务端固定的演示数据范围标识 |
| `fixture_version` | 用于缓存隔离、排错和展示数据版本 |
| `status` | `active` / `suspended` 等受约束状态 |
| `updated_at` | 控制面绑定更新时间 |

表上应设置租户外键、`(tenant_id, module_code)` 唯一约束、枚举或检查约束，并限制为管理员维护。生产主库可以保存这类租户、权限和绑定元数据，但不保存演示业务数据。

现有 `tenant_modules.module_settings` 是自由 JSONB。它可以承载展示配置，但不宜直接作为数据库路由的安全决策来源。若必须复用，至少需要固定 schema、数据库约束、管理员专属写入口和审计记录；独立的类型化绑定表更清晰，也更容易测试失败关闭行为。

请求不得接受或解释以下数据源选择输入：

- `demo=true`、`data_mode`、`source_key`、`fixture_key` 查询参数；
- 自定义数据源请求头或 Cookie；
- 数据库 URL、主机名、凭据或任意注册表键；
- 仅由前端状态保存、且未经主库绑定验证的租户属性。

## 4. 最小代码拆分

建议保持现有鉴权依赖，新增三个窄边界：

1. `get_control_session`：主库控制面会话。可先复用现有 engine，但命名需明确；身份、角色、租户、菜单、模块、SEM 身份和演示绑定都在此会话中校验。
2. `resolve_sem_data_scope(ctx, control_session, tenant_id)`：完成现有范围校验后读取可信绑定，返回不可变的数据范围对象，例如 `mode`、`source_key`、`control_tenant_id`、`data_tenant_id`、`fixture_key`、`fixture_version` 和 `read_only`。调用方不能自行拼装该对象。
3. `get_sem_read_session(scope)`：只从服务端固定注册表选择 engine。注册表由部署配置建立，键集合固定；它不读取请求输入中的连接信息。演示 engine 使用数据库只读账号，并尽可能在事务层设置只读。

业务查询应逐步移入 SEM read repository/service，由调用方显式传入 `scope` 和读取会话。所有演示查询都必须附带固定的 `data_tenant_id` 或 `fixture_key` 条件，不能只依赖数据库隔离，也不能把控制面租户标识直接当作演示库内租户标识。

不要在请求期间替换全局 `get_session`、修改全局 engine，或用 ContextVar 隐式改变鉴权会话。这些做法会让并发请求互相污染，且难以证明鉴权查询始终只进入主库。

## 5. 请求处理顺序

每个 SEM 读取请求按以下顺序执行：

1. 使用控制面会话校验 JWT 或 API Key，并加载用户、角色和身份状态。
2. 从既有路径、查询和请求体解析有效租户；租户值不一致时沿用当前 `422` 行为。
3. 校验目标租户范围、菜单权限、SEM 模块可用性和 SEM 身份。
4. 使用已经校验的租户 ID 在主库读取 SEM 演示绑定。
5. 普通租户保持现有正式业务会话；活动演示绑定通过固定 `source_key` 取得演示只读会话。
6. repository 在固定数据租户和夹具范围内查询，并返回现有响应字段。
7. 响应元数据补充非敏感的 `data_mode`、`data_version`、`as_of`、完整性状态和逐账户更新时间；不得返回连接信息或内部数据源键。

演示库故障返回明确的 `503 demo_data_unavailable`。未知数据源键、停用绑定、模块不匹配或缺少固定范围均视为服务端配置错误并失败关闭，不能尝试另一个库。

## 6. 首期 SEM 接入范围

第一阶段只迁移已经确认的四个只读业务路由：

| 接口 | 适配位置 | 保留的业务语义 |
| --- | --- | --- |
| `GET /api/v1/dashboard/cockpit` | cockpit read repository | 现有账户范围、日期、单位、缺报、逐账户更新时间；电话按钮点击不视为已支持指标 |
| `GET /api/v1/keywords/cockpit` | keyword list read repository | 账户过滤、实际统计窗口、CTR、缺失值和独立更新时间 |
| `GET /api/v1/keywords/cockpit/{keyword_id}` | keyword detail read repository | 关键词归属校验、地域、星期×小时；电话字段仅在原始字段明确存在且可解析时返回 |
| `GET /api/v1/search-terms/cockpit` | search-term read repository | 账户关联、请求窗口与实际窗口、已知小计和更新时间 |

模块详情页仍使用现有站内路由。后续是否纳入结构、告警、操作记录和任务读取，应在四个接口稳定后逐项决定，不应一次替换所有 ORM 查询。

`/dashboard/today`、分析报告、月报、导出和任何写接口不进入首期演示只读适配。现有演示运行时安全闸门继续生效，调度器、百度客户端、外部动作、写接口、AI 生成和 OAuth 流程保持禁用。

## 7. 返回语义

适配层只改变数据来源，不改变已经确认的指标含义：

- 电话按钮点击不等于拨通电话或有效咨询。
- 关键词报告花费不等于全部广告产品账户消耗。
- CTR 必须沿用各接口已确认的输出单位；repository 内应统一从原始比例或百分值转换一次，响应同时保留单位说明，禁止前后端重复乘以 100。
- 缺失日期与真实零值必须可区分。建议以请求日期序列和实际报告日期集合生成 `missing_dates`；只有存在报告行且指标为零时才认定为真实零值。
- 部分电话数据只能返回已知小计，并标识覆盖范围；不能用零填充未采集账户或日期。
- `as_of` 表示该响应所用数据的最新报告时间；逐账户更新时间用于指出不同账户的新鲜度差异。
- 数据不完整时仍可返回已有结果，但必须带机器可读的完整性状态、缺失账户或日期及原因。身份或权限不足继续返回鉴权错误，不能伪装成空数据。

缓存若在后续启用，键至少包含 `data_mode`、控制面租户、数据租户或夹具键、接口参数和夹具版本，避免正式与演示响应互相命中。

## 8. 必须覆盖的测试

### 8.1 身份和数据源选择

- 绑定正式租户的普通用户请求演示租户时，在访问演示 engine 前返回 `403`。
- 演示用户请求其演示租户时，先完成主库全部校验，再建立演示读取会话。
- 路径、查询和请求体中的租户不一致时返回 `422`，不访问业务数据源。
- `demo=true`、伪造数据源头、Cookie 或请求体字段不能改变数据源。
- 管理员请求正式租户时不能通过任何请求输入强制进入演示库。
- 绑定不存在、已停用、模块错误、来源键未知或固定范围缺失时失败关闭。
- 演示库不可用时返回 `503`，且不回退到正式库。

### 8.2 会话与隔离

- SQL spy 证明身份、角色、权限、租户和绑定查询只进入控制面数据库。
- SQL spy 证明演示业务查询只进入演示数据库；正式租户业务查询仍使用正式数据源。
- 演示数据库角色执行 `INSERT`、`UPDATE`、`DELETE` 和 DDL 均失败。
- 每个演示 repository 查询都携带固定数据租户或夹具范围；关键词详情不能枚举另一个夹具的对象。
- 并发请求分别访问正式和演示租户时，会话和 scope 不交叉。
- 登出或切换租户后的迟到响应继续被前端现有请求代次保护拦截，后端同时保持租户范围校验。
- 缓存测试证明正式/演示、租户、账户、日期和夹具版本之间不串数据。

### 8.3 业务语义

- 多账户、单账户、无权限、缺报、真实零值和部分覆盖分别有确定夹具。
- 请求日期窗口与实际报告窗口均可断言，缺失日期由报告日期集合识别。
- CTR 输入为比例和百分数的边界各有契约测试，输出单位一致。
- 电话按钮字段缺失时返回 `unavailable`；部分存在时只返回已知小计和覆盖说明。
- 演示请求不启动同步、调度、AI、缓存生成、状态更新、OAuth 或真实写调用。
- 登录仍使用原入口，站点不新增公开 URL。

## 9. 实施顺序与工作量

以下为单人净开发估算，不含数据库、部署审批和联调等待：

| 顺序 | 任务 | 估算 |
| --- | --- | --- |
| 1 | 控制面绑定模型、迁移、管理约束和 resolver 单测 | 1.5～2.5 人日 |
| 2 | 演示只读 engine/session 注册表、只读事务和故障映射 | 1～2 人日 |
| 3 | 四个 cockpit 接口迁移到 repository，补 scope 和响应元数据 | 3～5 人日 |
| 4 | 多库隔离、权限、并发、失败关闭和业务语义集成测试 | 2～3 人日 |
| 5 | 站内租户选择联调与运维观测 | 1～2 人日 |

建议先完成绑定 schema 和 resolver 契约，再接 engine，随后按 dashboard、关键词列表、关键词详情、搜索词的顺序迁移。dashboard 契约最稳定，可先验证双会话闭环；关键词详情涉及对象归属、地域和时段，风险最高，放在列表之后。

## 10. 开始实现前的阻塞项

1. 数据库负责人确认主库控制面绑定 schema，以及演示数据库、只读账号和网络连通方式。
2. 确认认证用户、角色、租户、菜单、模块和 SEM 身份只由主库维护；演示库不承载登录凭据或客户身份副本。
3. 确认服务端 `source_key` 注册表和密钥交付方式。连接串只能来自部署配置或密钥系统。
4. 确认演示读取是否复用现有业务表。当前 `baidu_accounts` 要求非空凭据字段，而演示数据不应依赖可用真实凭据；需要专用只读视图、演示账户模型或 repository 映射方案。
5. 将 `sem_tasks` 纳入受控迁移链，或明确首期不展示任务。当前主迁移 head 未建立该表。
6. 冻结首期详情范围和响应元数据字段，避免 repository 重构期间反复改变契约。

这些事项未确认前，可以完成接口设计和单元测试骨架，但不能安全地连接或装载隔离演示数据库。

## 11. 与现有演示工作的关系

- `SEM_DEMO_FIXTURE_PLAN.md` 继续定义确定性夹具数据及业务覆盖。
- `SEM_DEMO_RUNTIME_AUDIT.md` 继续定义运行时写入和外部调用安全闸门。
- 本文定义同域站内访问时，服务端如何在通过现有鉴权后选择隔离 SEM 只读数据源。

三部分应分别评审。夹具和安全闸门不因本适配方案而解冻；数据库迁移、数据装载、部署和真实联调仍需在阻塞项关闭后单独执行。
