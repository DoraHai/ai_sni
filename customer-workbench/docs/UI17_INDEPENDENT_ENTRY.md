# UI17：客户工作台独立入口

2026-10-09。用户要求修复可用性，并指出不应依赖旧驾驶舱登录入口。本轮在 UI16 首页修正之上补独立入口，未修改 SEM/SEO/GEO 后端、原 Auth 页面、账号表、Nginx 或数据库。

## 原因与方案

之前 production-entry 复用了跳转 `/login` 的 helper，且没有独立范围选择器；缺失 tenant/site 时让用户返回旧驾驶舱。页面虽独立构建，进入流程仍依赖旧产品。

现在直接打开 `/customer-workbench/`：未登录时显示客户工作台登录表单；已登录时调用现有 me/modules/tenants/workbench-sites 核对并选择空间。只有一个获准客户和一个可用站点时直接进入；多个时由用户选择，不偷偷取第一个。根路径查询参数由当前前端处理，沿用四文件发布包与现有静态路由，不增加域名/路径配置。

- 登录继续使用 `/api/v1/auth/login` 与 canonical session.setAuth，默认只保留当前会话；记住登录才使用原持久存储。
- 保留原页面的本地图形验证码交互。它不是服务端安全验证码；实际错误次数锁定、停用与权限仍由原后端处理。本轮没有移除或改动后端机制。
- 密码不写日志、URL、交接或自建存储。登录请求不自动重发，超时可重试；失败清空密码并换验证码。
- 客户/网站选择只读取服务端授权清单；客户绑定、SEO资格和稿件查看权限仍核验。进入后原 adapter 再核对具体 tenant/site，URL 不能授予权限。
- 站点为空、禁用、无权限、网络失败分别展示；不创建站点、不触发采集/生成/发布。
- 401 清原会话并返回本工作台登录，保留合法候选范围；不接收任意 redirect；畸形或重复参数不读取业务数据。
- 切客户取消旧请求；旧响应不能覆盖新范围。跨标签身份变化清当前选择并重读。顶部提供选择工作空间和退出；已有未保存稿件/未发送顾问消息仍提示。
- 共享账号与登录态是有意保留的单点登录：从这里退出也会清除同源原会话。独立的是产品入口、页面和发布包，不是第二套认证数据库。

## 本地证据

UI17 2项、UI15入口1项、UI06构建入口1项、host-session-adapter 5项通过，共9项。覆盖真实构建产物的独立登录、验证码错误不提交、登录拒绝、不记住登录、单范围直达、多客户选择、慢旧响应、空站点/403、401返回、390px与零业务写入。账号与数据全为本机夹具，不是真实客户验收。

初次 UI17 因 Edge 密码控件自身 data:image 内嵌图标被误计为外部请求而断言失败；已仅排除 data:（不产生网络请求），HTTP(S)仍严格同源并复跑通过。UI15旧测试的文本替换曾产生语法错误，已修正后通过；不是生产故障。

UI16 原来的17项结果保留；本次不重复无关数据库/模块检查。真实 AI 自由问答、全客户顾问会话、SEM/GEO业务接入不在本次新增范围，不能以入口完成代替这些能力完成。

## 发布

本轮截至该记录仅本地提交与制包，未合并或部署。沿用 Customer workbench artifact 显式静态发布流程；不发布原Auth或SEM包，不再次做路由迁移。线上仍以正式发布回执为准。发布后需验证根入口、登录失败/返回、普通客户站点及顾问消息；本地合成测试不等于生产验收。
